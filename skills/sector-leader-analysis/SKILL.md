# 板块龙头股分析（主线维度）

## 适用场景

- 识别一个板块/主线内真龙头（不是涨幅最大的，而是最持续的）
- 排除伪龙头（超跌反弹股、一日游涨停股）
- 评估龙头股的追高风险（还能不能追）
- 判断龙头切换（老龙头退位、新龙头接力）
- 查询/汇报 16:45 主线龙头分析（theme_leaders_*.md）与精筛（refine_theme_leaders_*.md）
- 查询/汇报 18:00 监控池交易机会（faded_watch_leaders_*.md）
- 核查 industry_themes.related_sectors 写库覆盖度（是否每个主线都有可拉成分股的板块）→ `scripts/verify_theme_sectors.py <开始日期> <结束日期>`（默认最近3个交易日；判据：✅=板块可拉成分股 / ⚠️=主线全部拉不到 / 🔍=缺 sectors 字段；2026-09-05 已核查 08-31~09-02 共29条记录36个板块全 ✅，报告存 `backtest_results/sectors_coverage_check_20260905.md`）

## 核心原则

**涨幅最大 ≠ 龙头。** 真正的龙头是带领板块上涨的旗手，不是从坑里弹回来的反弹股。

**判断龙头的三个标准：**

```
① 持续性：均线多头排列（MA5>MA10>MA20>MA60）且年线翻多，不是超跌反弹
② 引领性：板块启动前它就在涨，板块启动时它领涨
③ 逻辑性：有基本面/政策/事件支撑，不是纯概念炒作
```

## 产业主线框架

龙头分析**按主线聚类，不按单板块**。板块和龙头股都是主线上涨的结果，真正的交易主线是跨板块的产业逻辑。16:45 脚本从 industry_themes 当日 active/peaking 主线出发：股票池 = 主线覆盖板块大市值成分股(top10/板块, 市值≥300亿) ∪ 表格1概念命中主线的上榜股(同样≥300亿，**须属于主线 sectors 任一板块成分股才并入主池参与判定**；否则标记概念来源单独分组跟踪，不参与 RPS/场景/精筛/alpha 计算) → 池内均线验证 → 按主线聚类输出（板块/上榜股只是股票池来源，不再是输出维度）。

## 数据获取

两个真实数据源（16:45 脚本 fetch_theme_leaders.py 实际都在用）：

### 1. portfolio 库（root 无密码，板块脚本硬编码）

```bash
mysql -u root portfolio
```

- **industry_themes**（主线状态与 16:30 技术确认）：
```sql
SELECT theme_name, status, theme_date, consecutive_days, related_sectors, break_level, advice_signal
FROM industry_themes ORDER BY theme_date DESC LIMIT 30;
```
  - `status`：active / fading / peaking / ended（16:45 分析 active/peaking）
  - `break_level`：16:30 fetch_trend.py 回填的 MA 破位级别（16:45 只对 break_level<2 建池；NULL=16:30 断档，按未破位保守处理并在报告头标注⚠️）
  - `advice_signal`：16:30 建议信号（如 持有/减仓/观望）
  - `related_sectors`：JSON，含 sectors（行业板块 pt 代码）+ concepts（概念标签）+ major_concept

- **sector_summary**（板块统计入库版：industry_plates 二级行业上榜表 + concept_stocks 概念股上榜表）：
```sql
SELECT rank_no, name, detail FROM sector_summary
WHERE report_date='YYYY-MM-DD' AND table_type='industry_plates' ORDER BY rank_no;
SELECT name, detail FROM sector_summary
WHERE report_date='YYYY-MM-DD' AND table_type='concept_stocks'
  AND (name LIKE '%药%' OR name LIKE '%医%' ...);   # 按关键词过滤
```
  - detail JSON 含 zdf/zdf_d5/zdf_d20/sectors 概念标签；**zdf_d5/zdf_d20 仅作初筛/情绪参考；趋势判定一律用均线**

- **sector_congestion**（板块拥挤度，可能滞后 1 天以上）：
```sql
SELECT sector_name, stock_count, amount_ratio, congestion_level FROM sector_congestion
WHERE report_date='YYYY-MM-DD' ORDER BY amount_ratio DESC;
```

路径：`/home/agentuser/data/定时任务打包/data/plate/plate_YYYYMMDD.md`
- 表格1（概念股上榜，含 zdf_d5/zdf_d20）

## 核心分析工具

### 工具A：真伪龙头鉴别

**用均线结构做"照妖镜"**——涨幅只反映两点增量，均线（排列/斜率/年线位置）才反映趋势方向。

```bash
# 查目标板块成分股的均线结构（MA5~MA250）
westock-data technical <code> ma
```

| 分类 | 均线结构（主判据） | 涨幅特征（辅助） | 判定 |
|:----|:----|:------:|:----|
| 🟢 **真龙头** | 多头排列：价格>MA5>MA10>MA20>MA60 且 价格>MA250 | 5日涨幅大（>10%） | 持续上涨，趋势确认 |
| 🟡 **活跃股** | 站上MA20但MA60<MA120或年线压制 | 5日涨幅中（5~10%） | 跟涨，不是领涨 |
| 🔴 **超跌反弹** | 价格<MA20 或 均线缠绕（从年线下方弹起） | 5日涨幅大但20日为负 | 从坑里弹回来，伪龙头 |
| ⚪ **冷门票** | 均线空头排列，价格在所有均线下方 | 5日涨幅小（<5%） | 刚上榜，需观察 |

**判据速查：**
```
价格 > MA5 > MA10 > MA20 > MA60 且 价格 > MA250（年线翻多）
  → 🟢 真·慢牛：多头排列 + 长期趋势确认
价格 > MA5 > MA10 > MA20 但 MA60 < MA120 或 价格 < MA250
  → 🟡 中短期反弹/超跌反弹：长期均线仍压制，不是慢牛
价格 < MA5（跌破5日线）或 价格 < MA20
  → 🔴 短线破位/回调，趋势走弱
多头排列 且 BIAS_6 > 15%（或价格偏离MA20 > 15%）
  → 🟡 加速赶顶，追高警惕
```

### 工具B：龙头强度评估

| 维度 | 高分特征 | 低分特征 |
|:----|:--------|:--------|
| **均线结构** | **多头排列+年线翻多**：MA5>MA10>MA20>MA60 且价格>MA250（慢牛） | 均线缠绕/年线压制（超跌反弹）或 BIAS 过大（加速赶顶） |
| **上榜持续性** | 连续多天在板块成分股中 | 首次上榜 |
| **板块关联度** | 核心概念股，业务直接相关 | 边缘概念股，蹭概念 |
| **市值** | 100~500亿（弹性+安全） | <50亿（容易被砸）或>1000亿（弹性不足） |
| **涨停质量** | 换手涨停（有分歧有承接） | 一字板（买不到，开板就是顶） |

> ⚠️ **涨跌幅判据全部废弃**：5日/20日涨幅只反映两点间增量，丢失趋势路径；且"5日<20日"几乎恒成立，区分不了慢牛与"暴涨后滞涨/回撤"。慢牛是**趋势结构属性**，必须用均线判断（斜率、排列、回撤位置）。

### 工具C：追高风险评估

```bash
# 1. 查当前位置（相对MA20/MA60/MA250，BIAS_6乖离）
westock-data technical <code> ma
# 2. 查板块整体热度（上榜数是否在扩散）
# 3. 参照工具B的均线判据定位（低位/中位/高位）
```

| 位置 | 情绪 | 资金 | 判定 |
|:----|:----|:----|:----|
| 低位（刚突破MA20，价格<MA60或接近） | 未高潮 | 持续流入 | ✅ **可以追** |
| 中位（多头排列中段，价格在MA60~MA250之间） | 温和 | 持续流入 | 🟡 **谨慎追** |
| 高位（价格>MA250 且 BIAS_6>15% 乖离过大） | 高潮 | 开始流出 | ❌ **不能追** |
| 超跌反弹（价格<MA20，均线缠绕） | 短期爆发 | 游资行为 | ❌ **不能追** |

| 指标 | 安全 | 警告 | 危险 |
|:----|:---:|:---:|:---:|
| 均线位置 | 价格>MA20且<MA250 | 接近/刚突破MA250 | 远离MA250且BIAS_6>15% |
| MA250（年线） | 年线下方蓄势/刚翻多 | 突破但回踩 | 年线下方反弹（超跌） |
| 乖离 BIAS_6 | <10% | 10~15% | >15% |
| 板块上榜数 | 持续增长 | 高位震荡 | 骤降 |

### 工具D：龙头切换识别

```bash
# 对比前后两天板块成分股名单
# 看老龙头是否消失，新面孔是否出现
```

| 信号 | 含义 |
|:----|:----|
| 老龙头连续2天不在板块成分股中 | 龙头退位 |
| 新面孔连续2天涨幅>10% | 新龙头接力 |
| 板块上榜数没降但老龙头消失 | 内部轮动，不是退潮 |
| 老龙头和板块同时消失 | 板块退潮 |

### 工具E：市场场景匹配

**为什么需要场景**：同一个乖离值在不同市场场景下含义完全不同——趋势启动期 BIAS_6 8~15% 是正常突破乖离；高潮加速期同样乖离是见顶信号。**场景是乖离的语境**。

**函数：** `identify_market_scene(results, theme_name)`（fetch_theme_leaders.py + refine_theme_leaders.py 各一份，逻辑一致）

**五场景判定（以代码实现为准；判定顺序：高潮加速 → 趋势中继 → 趋势启动 → 退潮反弹 → 混沌期）：**

| 场景 | 判定条件 | 操作 | 止损 |
|:----|:--------|:----|:----|
| 🚀 **趋势启动** | 有真龙头 + 平均偏离MA10 >10%（刚突破加速） | 首仓介入 | MA20下方2% |
| 📈 **趋势中继** | 有真龙头 + 平均偏离MA10 3~10%（均值回归区域） | 加仓 | MA20 |
| ⚡ **高潮加速** | BIAS_6>15% 占比 >30% + 平均MA20斜率 >2%（高乖离+陡峭） | 减仓 | - |
| 🔄 **退潮反弹** | 超跌反弹占比 >50%（大部分在年线下方反弹） | 不参与 | - |
| 🌫️ **混沌期** | 无真龙头 / 其他混杂 | 观望 | - |

**判断依据（basis）示例：** `"真龙头3只，活跃股2只"` / `"平均偏离MA10 3.8%（均值回归区域）"` / `"高乖离占比33%（BIAS_6>15%的股票较多）"`

**场景化追高判断（工具C 场景匹配版）：**

| 场景 | 乖离含义 | 判定 |
|:----|:--------|:----|
| 趋势启动（刚突破） | BIAS_6 8~15%是正常突破乖离 | ✅ 可以追，回踩MA10是加仓点 |
| 趋势中继（回踩确认） | BIAS_6 3~8%是回踩后的正常位置 | ✅ 可以追，缩量回踩是确认信号 |
| 高潮加速（连续大涨） | BIAS_6>15%是加速赶顶信号 | ❌ 不能追，持有者减仓 |
| 退潮反弹（跌多弹一下） | BIAS_6可能<10%但均线空头 | ❌ 不能追，反弹是卖点 |
| 混沌期（方向不明） | 乖离无参考意义 | ❌ 观望，等主线出现 |

**⚠️ 精筛场景函数输入口径**：refine 版 `identify_market_scene` 入参是 `[r["st"] for r in refined]`（来自 parse_theme_leaders 解析主报告行），fetch 版入参是 analyze_pool 的 K线实算结果（非报告解析）——两处数据源不同，同一天可能给出不同场景，属预期。

**场景参与 A/B 分流**：混沌期/退潮反弹 → 该主线保留股整体禁 A级（只降 B级），汇总与可执行清单均标注🌫️场景观望降级。

## 分析流程

1. **确认主线归属**：查 industry_themes 当日 active/peaking 主线，读 related_sectors 确认目标板块归属
2. **取板块成分股**：sector_summary（industry_plates 按 rank_no 取）+ plate 文件表格2
3. **真伪龙头鉴别**：对每只成分股用**工具A**查均线结构（MA5~MA250）
4. **龙头强度评估**：对真龙头用**工具B**评估强度
5. **追高风险评估**：用**工具C + 工具E 场景**判断还能不能追
6. **龙头切换判断**：对比前后几天成分股变化（**工具D**）
7. **输出报告**：按下方模板

## 16:45 cron 产物解析（theme_leaders_YYYYMMDD.md，主线维度）

> 用户问"看一下今天16:45的执行结果/主线龙头分析"时，读此文件并按下面方法提取摘要。**板块和上榜股票只作为股票池来源，输出按 active/peaking 且未技术破位（break_level<2）主线聚类**。

**手动补跑（指定交易日）：**

用户要求"按X日收盘执行16:45龙头分析"（常见于周末补跑）时：

1. **不要用 cronjob action='run'**——job prompt 内部用 `$(date +%Y-%m-%d)` 取当天日期，周末/非交易日会找不到 plate_ 文件而失败；直接手动跑脚本并显式传目标交易日：
   ```bash
   bash /home/agentuser/data/定时任务打包/scripts/run_trend_leaders_daily_cron.sh 20260821
   ```
   （入口脚本默认日期=今天；支持 YYYYMMDD 与 YYYY-MM-DD 两种格式，日志/pid 文件名随 DATE_ARG）
2. **前置检查**：目标日 `data/plate/plate_YYYYMMDD.md` 必须存在（路径是 `data/定时任务打包/data/plate/` 子目录下）+ `industry_themes` 表有当日主线（16:00 生成）；检查 `/tmp/theme_leaders_daily_*.pid` 无存活进程（`kill -0 $(cat pid)` 返回 no）再启动——pid 文件存在但进程已死不会阻塞（入口脚本会覆盖），删掉仅卫生习惯，非必须
3. **轮询完成**：输出 `STARTED <PID>`，每 ~150s `ps -p <PID>` 检查，消失即完成；用 tail /tmp/theme_leaders_daily_<date>.out 确认 ✅ 全部完成、.err 无错误
4. **覆盖注意**：补跑会覆盖同名 `data/theme_leaders_YYYYMMDD.md`（当日已生成文件会被覆盖）
5. **汇报**：读尾部 `# 🎯 全场入场机会汇总（主线维度）` 提炼（覆盖主线数/优选区🌟/回踩观察👀/强度观察🔎前5）；用户要完整报告 → `MEDIA:` 直接发原始 md 文件，不裁剪

**文件结构**（16:45 cron 产物，路径 `/home/agentuser/data/定时任务打包/data/theme_leaders_YYYYMMDD.md`）：

- 头部：生成时间 + **「当日主线全景」段**（所有主线及其 status，active/peaking 破位标🔻）+ 技术破位降级段（break_level≥2 拦截明细）+ ⚠️无16:30技术确认段（break_level 为 NULL 时）+ 本次覆盖 active/peaking 未破位主线数（fading/ended 交由 16:00+16:30，不覆盖）
- 每条 active/peaking 且未破位主线一节 `## 🟢/🟠 主线名（状态：active/peaking）`，含：
  1. **主线元信息**：覆盖板块（related_sectors.sectors，pt代码）+ 覆盖概念（related_sectors.concepts）+ 股票池构成（N只 = 板块大市值龙头n + 表格1上榜股m，去重）+ **板块强度过滤**（🔻剔除破位板块 / ⚠️降权弱板块）
  2. **龙头验证表**：股票池内均线照妖镜结果（来源列区分 `板块[XX]`/`上榜[XX概念]`；RPS 为池内排名；⚪一般/数据不足 不上表）
  3. **🎯 市场场景匹配**：🚀趋势启动/📈趋势中继/⚡高潮加速/🔄退潮反弹/🌫️混沌期 + 判断依据 + 建议操作（首仓介入/加仓/减仓/不参与/观望）+ 止损位 + 场景化追高判断表
  4. **🎯 入场机会聚焦**：🟢 优选/🟡 回踩观察/🟡 观察
  5. **🚫 已剔除**：超跌反弹/弱势（跌破MA20/年线压制）
- 尾部：**🎯 全场入场机会汇总（主线维度）**（三层：优选区🟢置顶 → 回踩等待区🟡 → 观察区🔎，标注所属主线），cron 汇报优先引用此段

## 注意事项

1. **涨幅最大 ≠ 龙头。** 必须用均线结构鉴别真伪（多头排列+年线翻多）。
2. **超跌反弹股**短期涨幅再大也是伪龙头，因为它只是从坑里弹回来（价格<MA20、年线压制），不是带领板块上涨。
3. **龙头是会切换的。** 一个板块的不同阶段可能有不同的龙头。
4. **追高前先看位置。** BIAS_6>15%（乖离过大）或价格远离MA250的龙头，即使逻辑再硬，短期回调风险也大。
