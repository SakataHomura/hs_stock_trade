# 收盘全景汇总（Daily Market Summary）

## 触发条件
- cron 每日 19:30（周一至周五，job `dcfa7205d16d`，自动聚合并推送企微 LiuXiYang）
- 用户要求手动执行（如"按照周五的日期，用周五的结论执行一次"）

## 核心约束
1. **忠实汇总**：只聚合各环节文件中的既有结论，禁止自行推理、虚构、补充判断
2. **缺失标注**：当日某环节文件缺失，对应章节标注「⚠️ 异常：未获取到 {环节} 结论」，不编造内容
   - **例外：industry_themes 文件缺失可走 DB 恢复**（实测 2026-09-10）：16:00 环节文件可能漏生成，但主线数据已落 MySQL `portfolio` 库 `industry_themes` 表（`theme_date` 字段），逐行包含 status / consecutive_days / peak_count / break_level / advice_signal / score_heat / score_tech / score_fund，可完整还原 16:00 主线结论：
     ```bash
     mysql -uroot portfolio -e "SELECT theme_name,status,consecutive_days,peak_count,break_level,advice_signal,score_heat,score_tech,score_fund FROM industry_themes WHERE theme_date='YYYY-MM-DD' AND is_legacy=0 ORDER BY status,theme_name;"
     mysql -uroot portfolio -e "SELECT theme_name,status,break_level FROM industry_themes WHERE theme_date IN ('YYYY-MM-DD','前一日') AND is_legacy=0 ORDER BY theme_name;"   # 状态迁移对比
     ```
     报告第一节标注「⚠️ 环节异常：文件缺失但 DB 数据完整（落库时间），以 DB + 16:30 下游引用还原」，照常给出完整主线表+关键变化；可用 `created_at`（落库时间）与各环节文件 mtime 核对是否为同一批次执行（防重跑版本混入）
3. **时序硬约束**：必须在 18:45 筛选完成后运行（17:30 会缺 18:00/18:30/18:45 当日数据，已定 19:30）
4. **生成时间口径**：报告头部「生成时间」= **文件实际生成时刻**（写入时刻 / `stat -c %y` 的 mtime），**不得填计划点时间 19:30**。当日各环节被重跑覆盖时，聚合必然晚于计划点，头部与文末落款须同步写真实生成时刻，并在「版本来源说明」列出各环节重跑时刻。反例（2026-10-12）：文件实写于 22:18（17:30/18:00 在 21:16/21:37 才重跑完），头部却标 19:30 —— 与自身「版本来源说明」自相矛盾

## 输入文件（data/ 目录，{YYYYMMDD}=交易日）
| 环节 | 运行时间 | 文件 |
|---|---|---|
| 市场主线 | 16:00 | industry_themes_{YYYYMMDD}.md |
| 趋势主线 | 16:30 | trend_follow_{YYYYMMDD}.md |
| 趋势龙头精筛 | 16:45 | theme_leaders_{YYYYMMDD}.md、refine_theme_leaders_{YYYYMMDD}.md |
| 退潮监控 | 17:30 | faded_theme_watch_{YYYYMMDD}.md |
| 退潮监控龙头 | 18:00 | faded_watch_leaders_{YYYYMMDD}.md |
| 池外归纳 | 18:30 | outside_pool_themes_{YYYYMMDD}.md（.json 为 18:45 输入） |
| 池外筛选 | 18:45 | outside_pool_leaders_{YYYYMMDD}.md |

## 追溯查询：为什么选入X（用户问"为什么推荐/选入某股"）

用户对汇总报告中的某个标的提问时，按**文件生成链反向追溯**（不是猜，是读原始环节文件）：

1. **定位来源环节**：`grep -n "股票名" daily_summary_{YYYYMMDD}.md`，汇总表每行有「环节来源」列（如 `16:45 精筛（军工）` / `18:45 池外筛选` / `18:00 退潮监控`）
2. **读源头文件**（data/ 目录，与汇总同日）：
   - 16:45 精筛 → `refine_theme_leaders_{YYYYMMDD}.md`（五层漏斗全部判据数值：市值/MA20斜率/回撤/距MA10/量比/换手/PE/R:R/动量分档）
   - 16:45 候选池 → `theme_leaders_{YYYYMMDD}.md`（板块强度过滤、剔除原因：破位板块/超跌反弹/年线压制）
   - 18:45 池外 → `outside_pool_leaders_{YYYYMMDD}.md`（真龙头/候选/剔除）
   - 18:00 退潮 → `faded_watch_leaders_{YYYYMMDD}.md`
   - 主线背景 → `industry_themes_{YYYYMMDD}.md`（16:00 主线成色/状态）+ `trend_follow_{YYYYMMDD}.md`（16:30 场景判断）
3. **还原选入逻辑链**：主线成立（16:00）→ 场景可进攻（16:30，趋势中继才给A级，混沌期禁A级降B级）→ 股票池生成（板块强度过滤）→ 五层漏斗通过（16:45）→ 对比同批被剔除者（为什么是它不是别人：对照组剔除原因）
4. **关注实际持仓偏离**：追溯时顺带核对用户真实买入价 vs 报告入场区间/止损位，若现价已破止损要主动提示（用户可能没注意到）

> 实案 2026-09-02：用户问昊华科技为何入选——军工新爆发主线(16:00 成色13/15) → 趋势中继场景(16:30) → 军工池10只经板块过滤+均线照妖镜剩2只 → 五层漏斗昊华全过(市值541亿/距MA10+5.6%/动量5日+15%/R:R 2.81)而国睿科技 R:R 1.9 被剔 → 化工4只因混沌期禁A级降B级 → 昊华成唯一A级。追溯中发现用户48.80成本已跌破47.75止损，需提示。

## 报告结构（5 节）
1. **当前市场主线**：16:00 成色/状态（active/peaking/fading/ended）、强势度、上榜数
   - **链族归约展示（P2 D4）**：主线有 parent_theme 时按链族归约（19:30 GROUP BY parent_theme），子链并列展示（如 化工 链族下：化工-煤化链 / 化工-化纤链），标注「链族 X：N 条子链」
   - **三维评分明细（每条主线必带）**：H/T/F 分值（score_heat/score_tech/score_fund，0~3，来自 industry_themes_{YYYYMMDD}.md 的三维评分明细节）+ 16:30 修正后最终状态（若与 16:00 初判不一致标注「16:30 修正」；被场景门控降速的标注「场景门控 R1/R2」）
   - **状态语义披露**：peaking = 热度退坡但趋势+逻辑完好的**正常分级**（16:45 照常进池精筛），不是退潮；ended/fading 才对应退潮（17:30 监控池接管）；主动型主线活跃度用 H 值区分（H≥1 主升共振 / H=0 热度退坡）。门控层产生的 peaking 同理（R2 大跌/普涨日低位跳升降速）
   - **状态实时镜像说明**：主线状态是当日三维（H×T×F）的实时镜像，随 16:30 break_level 回填重算覆盖修正（允许正反向），**非趋势定格**——bl 在 0↔2 波动时 active↔peaking↔fading 可能快速翻转，属正常机制（交易闸门是 bl<2，状态翻转不直接影响进出场）；报告呈现单日状态即可，不加"状态频繁变化"式免责注释
   - **peaking 主线占比过高提示**：若当日主线多为 peaking 而非 active，是整体热度退坡信号（非主线消失），聚合时客观呈现，不加"无机会"式免责结论
   - **信号层/成分基线指标分离（P1-4，必做）**：报告中若引用链构成/上榜数变化 → 标「信号层」；引用成分变更率/保持率 → 标「成分基线」；**禁止混用**（信号层 Jaccard 0.38 ≠ 成分换血）
2. **趋势主线及龙头股**：16:30 场景判断（趋势中继→加仓等）+ 16:45 精筛龙头（A级/B级、R:R、入场判定）
   - **精筛全集完整性（必做）**：第二节与第五节「场景标签」必须完整覆盖 `refine_theme_leaders_{YYYYMMDD}.md` 的**三段全集**——①有候选（正常段）②空池（声明池=0）③**建池即全剔除**（声明池>0 但龙头验证表无合格标的）；**逐链枚举，禁止只列其中一部分**。反例（2026-10-12）：汇总仅列 2 条空池链，漏掉 2 条空池链 + 3 条建池即全剔除链（广告营销/影视内容/AI技术）
   - 引用 refine 的「⚠️候选不足，降级观察」标签时须注明是**链级（候选不足）**还是**股级降级**——同一段内可能有 A 级标的与链级 ⚠️ 并存（如招商公路 A 级 · 现在可执行，而其所在链标 ⚠️候选不足），写成「均标注降级」会造成误读
3. **退潮监控主线及龙头股**：17:30 监控池状态（watching/候选级别）+ 18:00 候选（均线低吸/平台启动）
   - **同名链方向标注（必做）**：17:30 报告含两区——「⚠️ 同名冲突（N 条，判据方向相反）」（主线池 active/peaking ↔ 监控池 trend_broken/trend_weak）与「✅ 同步主线（N 条，判据方向一致）」（主线池 active/peaking ↔ 监控池 trend_ok/revive_candidate）。本节遇同名链**必须标注方向**：冲突链注明「**取 16:00 主线口径为准**」，同步链注明「与主线池同向，18:00 候选照常产出」；**禁止**把 trend_broken 字样直接呈现为退潮结论（10-12 实证：金融科技-网络安全链 16:00 active 而本池 trend_broken，仅此 1 条为真冲突；银行产业链/医药 3 链为方向一致，若一并按退潮解读会吞掉 18:00 候选）
4. **池外主线及龙头股**：18:30 池外主线评分排行 + 18:45 候选（注明场景判定，如混沌期观望）
- **口径消歧注（必做）**：18:30 候选带 conflict 字段时按 3.4 加注——`conflict=true` → 「※池外口径与主线同名不一致」。防\"同名不同板块集合\"被误读为正常候选（status_constraint 已随 v1.2 四层归属退役，主营推导候选不携带该字段；**P2 B2 半票**：候选带 `weighted_vote`（主属全票+次属半票）时展示加权分值，注明「含次属半票」）
5. **交易机会收敛**：四板块去重汇总可执行标的（标注来源环节+入场判定）；无机会则明示「今日无明确可执行机会」

## 输出与推送
- 产物：data/daily_summary_{YYYYMMDD}.md
- 推送：wecom:LiuXiYang —— 先发完整报告文件（raw 不裁剪），再附每节 2-4 行要点 + 机会收敛清单

## 手动执行
- 直接按指定交易日聚合（先确认当日 7 环节文件齐全），不依赖 cron 内部 $(date)
- 执行前先读全部 7 环节文件；报告生成后按上述推送格式交付
- **补跑/重跑版结论优先**：聚合前先核对各环节文件 mtime——若某文件 mtime 明显晚于其 cron 时段（如次日凌晨重跑 17:30/18:00 修复判据），说明当日结论曾被修正，**以最新 mtime 版本为准**，并在报告头部标注版本来源（例：`17:30/18:00 为重跑后最新版`），避免把过期/错误结论混入汇总。重跑版与原始版结论可能相反（如主线🅲️→🅰️），标注可让读者追溯
- 推送用 `send_message` 在 cron 自动投递会话会被跳过（cron_auto_delivery_duplicate_target）——把推送内容直接放最终回复（含 MEDIA: 附件行）
