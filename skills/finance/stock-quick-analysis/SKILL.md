# 个股快速分析（轻量版）

> 与 `stock-analysis`（manus_trade A1 重流程，10-15分钟）区分：本 skill 是 Agent 模式直接取数快速出报告，约 1-2 分钟。数据接口统一用 `/home/agentuser/.hermes/scripts/finance_wrapper.py`。

## 输入

用户提供股票名称或代码（如"恒力石化"、"sh600346"、"宁德时代"）。

## 执行流程

### 第1步：搜索确认代码

```bash
python /home/agentuser/.hermes/scripts/finance_wrapper.py --data_type search --name "<股票名称>"
```

- 确认返回的 GP-A 类型代码（如 sh600346），代码必须小写（腾讯 API 大小写敏感）

### 第2步：核对 MySQL 持仓

```bash
mysql -u wish -p<DB_PASSWORD> llm_stock -e "SELECT * FROM positions WHERE status='holding' AND stock_id IN (SELECT id FROM stocks WHERE code='<code>');" 2>/dev/null
```

**持仓展示规范：**
- 成本价 = `open_cost`（首仓价，永不改变），**不是** open_price（均摊成本）
- 仓位 = 持仓市值 ÷ 500000（总资金50万）；持仓市值 = **现价 × 数量**（amount 字段可能是历史建仓口径，冲突时以现价×数量为准，amount 仅作参考）
- 建仓日期 = `open_date`
- 格式：【持仓信息】成本价：xx元 | 仓位：xx% | 建仓日期：xxxx-xx-xx

**open_cost/open_price 可信度判定（区间校验法）：** 两值差异大时，用 quotes K线核对 open_date 当日价格区间（最高/最低）：
- open_cost 落当日区间、open_price 超出区间甚至超过3个月最高价 → open_price/amount 口径失真（坏数据特征：open_price 常见于远超3月最高价），按 open_cost 展示盈亏
- 反之 open_cost 不在任何历史区间而 open_price 吻合当日区间 → 用 open_price 并向用户报备口径
- ⚠️ amount=open_price×qty 恰好相等**不构成**可信证据
- 推送前先完成口径校验，勿沿用历史报告数字

无持仓则报告不写持仓模块，仅标注"当前无持仓"。

### 第3步：主线匹配（portfolio 库 industry_themes）

> 板块主线结论（industry-themes-reasoning 每日16:00写入 portfolio 库）必须结合到个股分析——判断个股所处主线生命周期阶段（🟢active启动/🟡peaking见顶/🔴fading退潮），避免板块排名靠前但主线已退潮的误判。**连 portfolio 库，不是 llm_stock。**

```bash
# 3a. 取最近一日主线（优先当天；当天无记录则取 MAX 日期，报告标注实际主线日期）
mysql -u wish -p<DB_PASSWORD> portfolio -e "SELECT theme_date, theme_name, status, consecutive_days, peak_count, related_sectors FROM industry_themes WHERE theme_date=(SELECT MAX(theme_date) FROM industry_themes);" 2>/dev/null

# 3b. 在同日板块统计文件表格1中按代码找该股所属概念（代码必须与主线 theme_date 对应的文件同日）
grep -E "\| <完整代码> \|" /home/agentuser/data/定时任务打包/data/plate/plate_<YYYYMMDD>.md
```

- 板块文件：`/home/agentuser/data/定时任务打包/data/plate/plate_YYYYMMDD.md`（15:30 生成，与 theme_date 对应）
- 匹配逻辑：解析表格1"所属概念板块"列（中文顿号 `、` 分隔），与每条主线的 `related_sectors.concepts` 做**精确字符串交集**
- 命中多条（概念重合）→ 全部列出，按 status 排序（active > peaking > fading > ended）
- 未命中 → 标注"未命中当前主线"，并列出当日主线名（该股属独立行情）
- 个股不在表格1 → 用 security 概念列表与主线 concepts 精确比对兜底，报告注明比对来源（"未上榜板块统计；参考security概念列表比对，未命中当前主线"）；**禁止臆测编造概念归属**

**判定层次：**
- concepts 精确命中 = 主线核心标的（🟢/🟡/🔴按状态）；concepts+sectors 双命中 = 核心标的（强度更高）
- 仅二级行业∈主线 sectors = 板块弱相关（仍算"未命中主线"的独立行情，但提示板块景气关联）
- 概念名称近似 ≠ 命中（判字符串精确相等，语义相近/包含关系不作数，如"半导体材料"≠"电子材料"）→ 判未命中并注明"概念接近但精确比对未命中"
- 概念排名前/后（如 200+/723）都不改归属结论，只反映当日概念强度
- 板块排名强 ≠ 属于主线：主线 sectors/concepts 覆盖窄时，个股板块再强、排名再靠前，也不强行挂钩主线
- 新闻催化 ≠ 概念命中：归属只看 security 概念列表与主线 concepts 字符串交集，新闻/研报里出现产业链关键词不作数
- 表格1概念列命中且与 security 概念列表、主线 concepts 三方一致 → 可作为归属的强化证据

**grep 验证规则：**
- 必须用 `grep -E "\| <code> \|"` 管道符精确匹配表格1行，返回 0 才是真未上榜；返回全文件行数级别的大数字 = 模式写错（BRE 下 `\|` 是"或"语义）
- grep 返回空 ≠ 一定未上榜：先 `head` 文件头确认表格1列格式，再按名称 `grep -E "股票名"` 复核一次；两步都无命中才算未上榜
- grep 命中概念名 ≠ 一定在 security 概念列表：必须回看命中行上下文，确认命中落在 `**概念板块（按涨跌幅排序）：**` 行内，新闻区的同名词不算概念命中
- 确认某概念是否存在不能只看概念行前 N 字符（长概念行队尾可被截断）：用 `grep -o "概念板块（[^)]*）[^|]*" <code>_batch.txt | grep -o "<目标概念>"` 直接对概念行内精确确认
- **脚本化全量概念提取（批量校验主线命中用，2026-09-30 实战）**：批量分析需要把个股完整概念列表与主线 concepts 做精确交集时，用**行锚定正则**取 SECURITY 概念行并提取全部概念；勿用"按区块头 split + 按 `<br>` 或文末截断 + 字符类正则"的写法（曾静默返回空列表 → 误判"无精确命中"，且不报错）：
  ```python
  m = re.search(r'\*\*概念板块（按涨跌幅排序）：\*\*\s*(.*?)\s*\|\s*$', open(f'/tmp/qa/{code}_batch.txt', encoding='utf-8', errors='ignore').read(), re.M | re.S)
  concepts = re.findall(r'([^\[\],]+?)\[\d+\+?/\d+\]', m.group(1)) if m else []
  ```
  解析要点：① 概念行以行尾 `|` 收尾，锚 `\s*\|\s*$`（re.M）最稳定；② 概念名用惰性 `[^\[\],]+?` 匹配，**勿用 `[\u4e00-\u9fff()（）]+` 字符类**——混合半/全角括号（如"共封装光模块(CPO）"、"增强现实（AR）"）会断词；③ 排名列兼容 `200+/724` 用 `\d+\+?`；④ 提取后与主线 concepts 精确交集即可自动判命中，7只批量实测：生益命中3条 ended 主线（覆铜板/CPO/先进封装）、中天/福晶命中光通信（CPO concepts）、国睿命中新质战斗力——**勿只凭 parse_qa.py 截断输出（head -120 会裁掉概念行尾部）判断归属**，中天52个概念、福晶19个概念，全量列表与截断视图差异很大

**归属时效性（每日重比）：**
- industry_themes 每日重写，sectors/concepts 逐日收窄/扩张；主线状态非单调（ended 可重新激活、fading 可回 peaking、consecutive_days 跨状态连续累加）；个股侧 security 概念列表也可盘中→收盘剥离、跨日回补
- 归属判定**一律以当次查询的 MAX(theme_date) 实时结果重新精确比对**，禁止沿用前一日/早间报告或历史结论；跨日批量分析时每个 theme_date 都要重新比对，归属变化本身写进报告
- 主线日期 ≠ 今天（16:00前分析、隔夜分析）→ 报告标注"主线数据截至 <theme_date>"

**龙虎榜解析（westock lhb）：**
- 格式：头部行情行 + `**龙虎榜统计**` 表（Reason/TotalBuy/TotalSell/NetBuy）+ `**营业部明细**` 表（RankType/Rank/Name/Buy/Sell/HotMoneyTags）

- **累计型 Reason（2026-09-29 实战补充）**：`连续三个交易日内涨幅偏离值累计达20%` 这类累计型榜单天然覆盖多日，查询日无大波动（如生益 9/29 +0.78%）时必非当日触发 → 直接归为历史旧榜（按涨幅累计期归因资金方向），无需做单日量级校验；累计型榜单只看净买/净卖方向与席位结构
- **判当日新榜三条件（全部满足才算）：** ① header date/closePrice/changePct 与查询日吻合；② Reason 与查询日涨跌方向自洽；③ 偏离量级校验（个股涨跌幅 − 指数涨跌幅 ≈ Reason 阈值；**深市个股对照深证成指 sz399001，勿只查上证 sh000001**）。方向自洽但量级不足 → 该榜归属最近一次真实触发日
- ⚠️ **盘中新榜量级松弛补丁（2026-09-28 实战）**：盘中时点（如14:35）指数未收盘，瞬时偏离量级可能略低于阈值（案例：福晶 -9.1% vs 深成指 -3.3% → 偏离 5.8pp < 7%，但仍判当日新榜）。判定顺序：① header date = 查询日 且 成交额/换手与查询日吻合 → 优先信；② 该股近期（≥10个交易日）是否存在另一可比大跌日（能触发同样 Reason 的）→ **不存在**则收盘偏离大概率达标（个股逼近跌停/指数收窄），判当日新榜，勿因瞬时量级不足机械归属旧日；仅当存在另一可比触发日时才归属该日并标"历史旧榜"
- **旧榜触发日定位法（2026-09-30 批量实战）**：方向矛盾/累计型旧榜需要"归属最近一次真实触发日"时，用已有 quotes 文件扫日线涨跌幅定位——写个小函数遍历 K 线行（`parts[3]` 为涨跌幅%），找与 Reason 匹配的最近交易日：`日涨幅偏离7%` → 最近一日涨跌幅≥7%（如沪电 9/30 查询日 -2.84% 返回"日涨幅偏离7%"→ 扫日线定位 9/07 +10.00% 涨停日）；`连续三日累计20%` → 找最近三段连续上涨累计≥20% 的区段（如生益 8/25~9/07 段）。定位后再按触发日归因资金方向，可顺势补充该日前后板块语境（如"9/07 涨停日为 AI PCB 高潮日"）
- 已识别过的旧榜（同 Reason+同金额跨查询日重复返回，header 每次刷新为查询日价格）→ 直接标"历史旧榜（该笔已多次查询到）"，不必每次重做量级校验

### 第5步：结构定位与 ATR20

**结构定位（必做，防止只看近10-15日K线误判位置）：** 从近3个月K线逐日梳理：

| 检查项 | 识别方法 | 意义 |
|:----|:----|:----|
| 前高/压力位 | 区间最高收盘价/最高价 + 顶分型高点 | 突破目标位、压力位 |
| 前低/支撑位 | 区间最低点 + 底分型 | 回调防守位、止损参考 |
| 箱体/平台 | 连续≥5日横盘的价格区间 | 突破上沿=趋势启动 |
| 突破 | 收盘放量突破前高/箱体上沿 | **关键节点**，标记日期 |
| 回踩 | 突破后缩量回踩，不破突破位/MA5 | 回踩有效=洗盘 |
| 确认 | 回踩后再放量上攻创新高 | **回踩确认完成=右侧买点** |
| 低点抬高 | 回调低点一次高于一次 | 上升结构健康 |

**位置定位（必写结论）：** 当前价格处于哪个阶段——① 箱体内震荡 ② 突破初期 ③ 突破后回踩中 ④ 回踩确认完成/主升初期 ⑤ 加速赶顶（放量滞涨/长上影）。

**ATR20 计算口径：** 从近3月K线（开/收/高/低四价）计算，报告引用统一写百分比：
- TR_t = max(高_t − 低_t, |高_t − 收_{t−1}|, |低_t − 收_{t−1}|)
- ATR20 = 最近 20 个交易日 TR 的均值；ATR20% = ATR20 ÷ 最新收盘价 × 100%
- 用途：① 衡量个股当前波动水平，辅助判断结构位止损的容错空间与目标空间是否合理；② 波动偏低的个股波段空间有限，报告需注明，参与与否由用户权衡；③ 波动水平随行情变化，止损位/仓位按最新值重估
- 口径与池子链路一致：refine_theme_leaders calc_rr 用同一 ATR20
- **自定义 execute_code 解析 quotes 文件计算 ATR20 的坑（2026-09-25 实战）**：quotes K线行末 VOL_MA120 列后**还有收尾 `|`**（行形如 `| 2026-06-25 | 95.9 | ... | 388435 | -- |`），正则 `... ([\d.]+|--)$` 锚定行尾必失败（返回空→ZeroDivisionError）；正确做法：`parts = [p.strip() for p in line.strip().strip('|').split('|')]`，要求 `len(parts)==14` 且首字段匹配 `^\d{4}-\d{2}-\d{2}$`，再 float() 转换；缠论分型/笔行（`| 顶分型 |`）会被该长度检查自然排除，无需单独过滤
- ⚠️ **ATR20 列索引对照表（必背，2026-10-08 实战踩坑）**：14 列 0 索引 = `[0]日期 [1]开 [2]收 [3]涨跌% [4]高 [5]低 [6]量 [7]MA5 [8]MA10 [9]MA20 [10]MA30 [11]MA60 [12]VOL_M5 [13]VOL_MA120`。**计算 TR 必须用 high=parts[4]、low=parts[5]、close=parts[2]、prev_close=klines[i-1][2]**——误把 parts[5]/parts[6] 当高低（实际是低点/成交量）不会报错，会静默算出 ATR20% 高达数十万 % 的荒谬值（本次实测 353471%），且高/低/量三者全错位；**结果合理性自检：A 股正常 ATR20% 在 1%~10% 区间**，出现 >100% 立即怀疑列索引而非数据。已验证代码：
  ```python
  for i in range(len(klines)-20, len(klines)):
      high, low, close = float(klines[i][4]), float(klines[i][5]), float(klines[i][2])
      prev_close = float(klines[i-1][2])
      tr = max(high-low, abs(high-prev_close), abs(low-prev_close))
      trs.append(tr)
  atr20 = sum(trs)/20
  atr20_pct = atr20 / float(klines[-1][2]) * 100   # 以最新收盘为分母
  ```

### 生命周期分析（周线为主、日线为辅，至少1年）

> 参考 A1 lifecycle_analysis（7阶段生命周期体系）移植的中期判断维度；只做**方向性阶段判定**，不引入 A1 的仓位乘数/止损ATR倍数等执行级系数（与轻量版"给方向不给执行方案"哲学一致）。**周线为主、日线大结构为辅**——日线短期波动（几天MACD柱、单日量能）不作为中期判断依据。

**数据来源：**
- 周线 = 第4步 4d 输出（lifecycle_weekly.py，默认80周≈1.5年，满足"至少最近1年"；含周线MA5/10/20、MACD(12,26,9)、RSI14、52周高低点/区间位置、周量比、近12周K线）
- 日线大结构 = 第4步 4a quotes（近3月，MA20/MA60/缠论）
- 周线数据不足20周（次新股）→ 回退日线大结构独立判定，报告标注"⚠️ 周线数据不足，仅依赖日线大结构"

**行情解剖三问（判定前必答）：**
1. 行情从哪里来？周线走势类型（上涨/下跌/盘整）、运行时间与幅度（年内高低点→当前位置）
2. 行情在什么位置？周线均线排列（多头/空头/缠绕）、MACD 零轴上下/红绿柱、52周区间位置
3. 正在发生什么变化？周线级别变化（均线转向/MACD 金死叉/RSI 位置）、日线大结构（站稳/跌破关键均线）

**生命周期 7 阶段定义（参考 A1；各条件独立判断，满足 ≥3/4 阶段成立；数值为 A1 参考阈值，以结构定性为主，不作机械门槛）：**

| 阶段 | 周线条件 | 日线条件 |
|:----|:----|:----|
| T1 趋势萌芽 | ①自年内低点反弹明显（参考>10%）且本周收盘站上周MA10 ②MACD零轴下金叉，或绿柱连续缩短（肉眼可辨） | ③MA5>MA10>MA20多头初步形成，MA20走平或开始向上 ④站稳MA20上方，近5日未创新低 |
| T2 趋势成长 | ①MA5>MA10>MA20多头排列且MA20向上 ②MACD零轴上方运行，红柱持续放大或稳定（无连续2周明显缩短） | ③价格MA20上方运行，MA20稳定向上 ④上涨放量、回调缩量（量价健康，定性） |
| T3 趋势成熟 | ①MA5与MA20间距显著扩大（均线发散，肉眼可辨超近一年大部分时间） ②RSI进入高位区（参考>70），或RSI顶背离（价格贴近52周高点但RSI未创新高） | ③加速上涨后开始震荡或出现长上影 ④MACD顶背离结构，或DIF/DEA高位死叉 |
| T4 趋势衰退 | ③MACD红柱开始缩短或DIF走平 ④放量下跌周K线（本周量明显大于前几周且收阴） | ①收盘价有效跌破MA20（连续2日）②MA5拐头向下且死叉MA10 |
| R1 震荡无序 | ①MA20走平，价格反复穿越MA20 | ②高低点未被反复确认，无清晰箱体 ③量能无规律放大缩小 ④板块无明确趋势方向 |
| R2 震荡成熟 | ③MA5/MA10/MA20靠拢或缠绕 | ①清晰箱体（上下轨被触及≥2次，价差明显）②量能整体萎缩 ④板块内涨跌比趋于平衡 |
| R3 震荡末端 | ③近几周振幅连续收窄 | ①量缩至极低（地量）②均线高度粘合（MA5/10/20间距很小，参考<2%）④地量后小阳线企稳/长下影/十字星 |

**判定期律（防抖动）：**
- 多数确认制：≥3/4 条件成立才定阶段；2/4 视为"预警转换"，不锁定新阶段
- 阶段切换需**连续2周**（周线条件）或**连续2日**（日线条件）满足；单次触发后次周不满足 → 维持原阶段并标注"预警转换"
- T2 与 T3 同时满足 → 取 T3（过热优先）
- 候选池约束：周线背景定性决定可评估阶段（上涨初期→T1/T2；上涨中段→T2/T3；上涨末期→T3/T4；下跌趋势中→R1；下跌末端筑底→T1/R2/R3；盘整→R1/R2），候选池外不评估
- 板块MA20向下且板块20日涨幅排名靠后（后30%）→ 个股阶段降一级（如T2→T1），报告标注"⚠️ 板块弱势拖累降级"

**阶段→交易倾向（方向性，不量化仓位）：**
- T1 萌芽：趋势刚启动，观察为主；待突破/回踩确认再介入（呼应结构定位②突破初期）
- T2 成长：健康趋势，持有可拿；回踩确认（④）可介入
- T3 成熟：过热，追高谨慎；持有者注意兑现/减仓（呼应⑤加速赶顶）
- T4 衰退：禁开仓；持有者按 MA20/结构位清仓
- R1 无序：无方向，观望
- R2 成熟：箱体操作，等放量突破再追
- R3 末端：变盘窗口，等方向选择（放量突破可追，破位回避）

**主线×生命周期共振（写入报告的交叉判断）：**

| 组合 | 含义 |
|:----|:----|
| 🟢主线 + T1/T2 | 顺风共振：产业启动/成长 + 个股趋势健康，可积极评估 |
| 🟡peaking + T2/T3 | 双过热苗头：产业见顶迹象 + 个股成熟，遵守兑现纪律 |
| 🔴fading + T4 | 双退潮：产业退潮 + 个股破位，只减不加 |
| 🟢主线 + T4 | 个股掉队：产业好但个股趋势破坏（换股信号） |
| T1/T2 + 未命中主线 | 独立行情：强≠可持续（沿用现有口径） |

### 市场风格结构修正（大盘环境 × 个股市值）

> 引用 market-state-analysis（每日19:00）产物读大盘环境，结合个股总市值分档，对交易建议做"顺/逆风格"修正。核心原则：**环境是背景、个股是主体**——修正只调整结论倾向，不改变结构/生命周期/主线等自身判断；弱势环境下个股自身强信号才可保留。

**数据来源：**
- 市场状态 = 第4步 4e 读取最近一期 market_state_<日期>.md：状态结论（趋势/位置/宽度）、风格结论（大小盘/成长价值/动量）、结构结论（分化/权重vs题材）、策略含义（仓位倾向/风格倾向/风险）

**态势×倾向修正（读 market_state"状态结论"与宽度）：**
- **弱势/防御**（上涨占比<40%，或6指数多数偏空）：整体降一档谨慎——可追→等回踩、等回踩→观望为主、持有→防守提示（破位即走）；**结构分化且个股属强势方向（小微盘/主线内）可豁免**，但开仓仍低配

- 普涨/普跌（贝塔主导）→ 普涨日可持有；普跌日暂缓开新仓（个股结构再好也等市场企稳）

**多因子共振排序（冲突时按此为主次）：**
1. 个股自身（结构定位+生命周期+量价）—— 主体，不可被环境覆盖

```
- **持有窗口：以 10 日左右为评估周期；超期未兑现，重新评估持有逻辑（降暴露，非机械清仓，勿与结构位止损冲突）**
- **目标口径：只给"近端前高 = 第一压力位"（参考，非承诺）**；标注第一压力距现价的远近——近：兑现相对可及但非保证；远：属远期结构，不作短线目标
- **止损容错校验：止损参考 = 结构位（MA10/MA20/前低）；用 ATR20 衡量结构位距现价的容错空间是否合理，不足 → 提示"容错不足、仓位下调或延后入场"，不自动改止损价**
- **低波动提示：无持仓且 ATR20 明显偏低 → 报告注明"波动偏低，短线目标空间有限"，是否参与由用户权衡**；有持仓照常做持有/减仓管理
- **R:R 边界：R:R 不作为独立买卖依据**；若引用，仅作风险结构描述，与胜率参考同框展示
- 结论置信度：按下表分级强制附带依据与风险边界
- 风险提示

**结论置信度分级（强制）：** 结论必须给出依据与风险边界，注明是历史参考、非个股预测。

| 结论强度 | 必须附带 | 示例 |
|---|---|---|
| 可追/买入 | 依据说明 + 风险边界（仓位自行控制） | "可追：放量突破确认+量价配合；短线方向低胜率，仓位自行控制、预留容错" |
| 等回踩/观望 | 无持仓默认不推的说明 | "观望，无持仓默认不推；回踩 XX 企稳再评估" |
| 减仓/清仓 | 结构位/持有逻辑依据 | "减仓：破 MA10(XX)；持有超期未兑现按时间止损" |

禁用确定性表述（出现即不合格）：**"必涨"、"主升浪确认"、"目标价 XX 元"** 等无依据支撑的承诺性措辞。
```

## 批量持仓快速分析模式（收盘后 cron 用）

用户要求"对当前持仓做快速分析并逐只推送企微"时使用。每只股票=上面第2-7步完整流程（含生命周期分析与市场风格修正环节），但**分析完成立即推送该股**，最后推汇总表。

### 流程

1. **查全部持仓**（含名称/代码/open_cost/数量/金额）：
```bash
mysql -u wish -p<DB_PASSWORD> llm_stock -e "SELECT p.id, s.code, s.name, p.position_id, p.open_date, p.open_price, p.open_cost, p.quantity, p.amount FROM positions p JOIN stocks s ON p.stock_id=s.id WHERE p.status='holding' ORDER BY p.updated_at DESC;" 2>/dev/null
```
2. **数据批量落盘**（推荐混合模式）：一个 background bash 循环把所有股票 quotes+batch+westock-data+周线 输出重定向落盘 `/tmp/qa/<code>_{quotes,batch,lhb,blocktrade,margintrade,weekly}.txt`，脚本和日志文件名加**日期后缀**（`fetch_all_YYYYMMDD.sh` / `fetch_log_YYYYMMDD.txt`）。⚠️ **后台化方式二选一**：用 terminal(background=true)+`notify_on_complete` 可被 process 工具跟踪；用 shell `&` 后台化则 **process 工具查不到该进程**（`process wait` 报 not_found 属正常、勿当失败），直接 `cat fetch_log_YYYYMMDD.txt` 看到 `ALL_DONE` 即完成——实测 7 只全量 fetch（quotes+batch+3×westock+weekly）约 30-40 秒，数据量小时也可前台直接跑。要点：finance_wrapper（4b）调用加 `2>/dev/null`（过滤 Pydantic 警告）；westock-data 输出 `2>&1` 保留；lifecycle_weekly.py 加 `2>/dev/null` 且 stderr 无内容；begin/end 日期按实际分析日重算（近3个月）；落盘期间可并行做主线匹配：
```bash
mkdir -p /tmp/qa && cat > /tmp/qa/fetch_all_$(date +%Y%m%d).sh << 'EOF'
#!/bin/bash
codes="<code1> <code2> ..."   # 持仓代码空格分隔（从第1步持仓查询结果填入）
for c in $codes; do
  python /home/agentuser/.hermes/scripts/finance_wrapper.py --data_type quotes --code "$c" --begin_date "$(date -d '-3 months' +%Y-%m-%d)" --end_date "$(date +%Y-%m-%d)" 2>/dev/null > /tmp/qa/${c}_quotes.txt
  python /home/agentuser/.hermes/scripts/finance_wrapper.py --data_type batch --code "$c" --data_types "security,fund_flow,news" --fund_flow_days "10" 2>/dev/null > /tmp/qa/${c}_batch.txt
  node /home/agentuser/.hermes/skills/westock-data/scripts/index.js lhb "$c" > /tmp/qa/${c}_lhb.txt 2>&1
  node /home/agentuser/.hermes/skills/westock-data/scripts/index.js blocktrade "$c" > /tmp/qa/${c}_blocktrade.txt 2>&1
  node /home/agentuser/.hermes/skills/westock-data/scripts/index.js margintrade "$c" > /tmp/qa/${c}_margintrade.txt 2>&1
  python3 ~/.hermes/skills/finance/stock-quick-analysis/scripts/lifecycle_weekly.py --code "$c" --weeks 80 2>/dev/null > /tmp/qa/${c}_weekly.txt
done
echo "ALL_DONE"
EOF
chmod +x /tmp/qa/fetch_all_$(date +%Y%m%d).sh && bash /tmp/qa/fetch_all_$(date +%Y%m%d).sh > /tmp/qa/fetch_log_$(date +%Y%m%d).txt 2>&1 &
```
⚠️ **shell `&` 后台与 process 工具不互通（2026-09-29 实战）**：上面代码块用 shell `&` 启动时，`process wait <pid>` 返回 `not_found` 是**正常现象**（进程工具只跟踪 terminal(background=true) 启的会话，不跟踪 shell `&` 作业）——勿当失败重跑；直接 `cat /tmp/qa/fetch_log_YYYYMMDD.txt` 看到 `ALL_DONE` 即完成。实测 7 只全量（quotes+batch+3×westock+weekly）约 30-40 秒跑完，落盘期间做主线匹配正好；若想用 notify_on_complete 则须改用 terminal(background=true)：`bash /tmp/qa/fetch_all_YYYYMMDD.sh > /tmp/qa/fetch_log_YYYYMMDD.txt 2>&1`
3. **紧凑解析**：用本 skill 附带 `scripts/parse_qa.py` 一次输出全部关键信息（K线近28行/缠论/SECURITY关键字段/FUND_FLOW历史/NEWS标题/lhb/blocktrade/margintrade），批量分析全程无需逐个 read_file：
```bash
python3 ~/.hermes/skills/finance/stock-quick-analysis/scripts/parse_qa.py <code> 2>/dev/null | head -120
# ⚠️ skill 目录挂在 finance 分类下（~/.hermes/skills/finance/stock-quick-analysis/），裸路径不存在；找不到时 find /home/agentuser/.hermes -name parse_qa.py
# 周线生命周期数据 parse_qa.py 不含，单独 read_file /tmp/qa/<code>_weekly.txt 读取
# 市场环境（第4步4e）整批只读一次：read_file <ls -t 最新的 market_state_*.md>，勿每只重复读
```
4. **每只分析完立即推送**（写推紧耦合：write_file 写 msg 后立即 push，确认 `{"errcode":0,"errmsg":"ok"}` 再下一只；推送方法见下节）
5. **全部完成后推汇总表**（最后一条消息）：Markdown 表格（代码/名称/现价/今日涨跌/成本/仓位/盈亏/建议）+ 总仓位 + 共性风险，注明"本建议基于当日收盘数据"。**压轴前覆盖检查（必做）**：`ls /tmp/qa/msg_*.txt` 与持仓代码清单逐一比对，确认每只都有 msg 且全部推过；少一只先补推再发汇总表。已发汇总表才发现漏推 → 立即补推并标注"（补发）"
6. **汇总表构建防坑**：每只股票用一个 dict（`{"code":..,"name":..,"price":..,"cost":..,"amt":..}`）或显式 float() 转换所有数值字段；金额字段 float() 后再 sum，带符号百分比字符串不能参与计算；execute_code 汇总脚本每次从空模板重写/全量检查，勿复用跨会话旧脚本（残留变量会 KeyError）

### 中断/压缩恢复模式

cron 批量任务中途上下文压缩/重启后恢复：**先查 /tmp/qa/ 已有产物再决定是否重做**。
1. `cat /tmp/qa/fetch_log_YYYYMMDD.txt` 见 `ALL_DONE` = 当日数据落盘已完成，跳过 fetch
   ⚠️ **跨日新会话必须先查文件时间戳**：`ls --time-style=+%F_%T /tmp/qa/` 带完整日期（`+%H:%M` 会丢日期把跨日历史残留误看成当日），且日志文件名日期后缀与当日一致才可用——仅凭 ALL_DONE 跳过 fetch 会拿到昨日收盘数据做当日分析；恢复模式只适用于"同一任务中途压缩/重启"，跨日一律重跑 fetch 覆盖
2. `ls /tmp/qa/msg*.txt` 看哪些消息已写好（压缩前 write_file 的文件仍在磁盘）——已写的读取校验后直接推，只补写缺失的

⚠️ **压缩上下文可能携带幻觉持仓/行情（恢复第一优先级校验，2026-09-24 实战踩坑）：**
- 上下文压缩后的摘要可能"记得"一套与 DB 完全不同的持仓：本实例摘要声称持有精达股份、福晶代码 sh300042、中天现价 18.16/成本 13.45，实际 DB **无精达持仓**、福晶实为 sz002222、中天现价 34.80/成本 35.91——代码前缀/数量/成本/价格全部对不上
- 恢复第一动作永远是**重查 MySQL 持仓清单**（第1步 SQL），以 DB 为唯一 ground truth；再对每只持仓用腾讯 API 批量实时价抽查（gbk 解码一次查全部代码）
- 磁盘上已存在的 msg_*.txt 仅作草稿：先 read_file 校验数字（代码/现价/成本/数量），与 DB 持仓+腾讯实时价**任一不符 → 整条重写，禁止直接推送旧 msg**；多条全不符 = 整批重写，勿逐条修补
- 复用落盘数据文件三条件（齐备才可跳过 fetch）：① fetch_log_当日 ALL_DONE；② 文件时间戳为当日收盘后（`stat -c "%y"`，或 `ls --time-style=+%F_%T`）；③ quotes 文件内含当日 K 线行（`grep -c "当日日期" <code>_quotes.txt` 返回 ≥4）。当日数据文件本身通常可信（脚本按持仓清单拉取），幻觉主要出在"摘要叙述"和"旧 msg 文件"里
- ⚠️ **quotes 当日行 grep 计数不是硬门槛（2026-09-29 收盘实测）**：收盘后全新 fetch 的 quotes 中，当日日期按 K 线行精确匹配（`grep -c "| 2026-09-29 |"`）通常只返回 **1**（当日K线就一行，缠论分型/笔行不匹配带管道符模式），勿因 <4 误判数据不可用而重复 fetch；更可靠的**盘中 vs 收盘判别**：`tail -3 <code>_quotes.txt` 看最后K线日期 + 与腾讯 API 实时价交叉验证——⚠️ **盘中当日K线是否写入不保证一致（三次实测：写入2次/未写入1次，2026-09-29 vs 10-08 vs 10-09）**：09-29 盘中 14:36 实测最后一行K线=上一交易日（当日未写入）；**10-08 盘中 14:40 实测 7 只持仓、10-09 盘中 14:35 实测 5 只持仓均全部已写入当日K线（实时 bar，价/量为盘中瞬时值）→ 倾向"多数情况下盘中已写入当日bar"**。判别：最后K线=当日且价≈腾讯实时价 → 盘中未收盘 bar，结构定位/ATR20 以已收盘完整K线为主、当日 bar 为辅（标题标"盘中"）；最后K线=上一交易日 → 盘中未写入 bar 或休市；收盘 run 最后一行才是分析日。节后首个交易日同理：16:00 主线推理未跑，MAX(theme_date)/market_state/板块文件仍为节前最后交易日，盘中 f[30] 时间戳为当日即确认交易中
- ⚠️ **weekly 文件防空（fetch 无错误处理）**：fetch_all.sh 最后一行才 echo ALL_DONE，周线脚本失败只生成空文件、ALL_DONE 照常打印。恢复/复用前用 `wc -c /tmp/qa/*_weekly.txt` 确认每只 >100 字节；**正常体积随脚本版本变化（2026-09-29 实测精简版约 1.5KB 即完整 82 周输出，勿机械套用早期 8KB 标准）**，内容校验以含 `[周线生命周期数据]` 标题 + 近12周K线表为准；空文件（0字节/无标题）=该股周线拉取失败，需单独补拉该股 weekly 后再分析（禁止用空 weekly 判生命周期）
⚠️ **同日多 run 数据复用边界（2026-09-25 实战）**：/tmp/qa 存在**当日更早 run**（如 14:00 盘中任务）的 fetch 产物时，三条件中"时间戳为当日收盘后"是硬门槛——**14:35 盘中快照即使 fetch_log ALL_DONE、quotes 里 grep 得到当日日期，也绝不能用于 21:00 收盘分析**（当日K线未收盘、SECURITY 是盘中价）；收盘后任务一律重跑 fetch 覆盖。时间戳检查用 `stat -c "%y %n" <file>`；⚠️ `ls --time-style=... <file1> <file2>` 多文件参数只打印文件名不打印时间（无 -l 时看不到时间戳，易误判"已有数据"）。收盘任务的 fetch 产物时间戳应 ≥ 15:00（如 21:0x）；早于收盘 = 必重跑。盘中 run 的 quotes 里当日日期 grep 计数也常 <4（缠论未确认、行数少），与三条件③同向验证。**同日已有更早 run 的 fetch_all_YYYYMMDD.sh/fetch_log 时，本次收盘 fetch 脚本/日志用 `_close` 后缀**（`fetch_all_YYYYMMDD_close.sh` / `fetch_log_YYYYMMDD_close.txt`）区分，避免与盘中产物混淆（数据文件本身照常覆盖，2026-09-28 实战）。
3. 推送前仍走腾讯 API 校验（见下节）
4. 全部推完最后推汇总表
⚠️ 持仓查询疑似截断：`mysql -e` 终端只回显 1 行（有数据却看不到）时，重定向 `| tee /tmp/qa/holdings.txt` 落盘再 read_file，勿误判"无持仓"

### 类型二变体（数据全部已落盘时的省调用推送）

若全部股票数据已先落盘（/tmp/qa/<code>_batch.txt 等），可先一次性解析 → 拼全部消息 → 循环推送（一批≈3个 execute_code 完成）。仅适用于数据已齐的补跑/重跑场景；正常实时分析仍用"批量落盘→逐只分析→逐只推送"（用户要求分析完成即达）。

**batch 文件解析要点：** 区块头是 `====== [SECURITY] ======` 形式（等号包裹），用通用提取函数按区块名定位；quotes K线行必须严格匹配全部14列（时间/开/收/涨跌/高/低/量/MA5/MA10/MA20/MA30/MA60/VOL_M5/VOL_MA120）——**VOL_MA120 列早期可能为 `--`**（K线不足120根时 MA 列都是 `--`），正则末组必须兼容 `([\d.]+|--)`，否则该行整行匹配失败；裸匹配 `^\| \d{4}-\d{2}-\d{2} ` 会同时命中缠论分型行导致 float() 转换崩溃，分型/笔另用 `^\| \d{4}-\d{2}-\d{2} \| (顶分型|底分型|向上笔|向下笔) \|` 单独提取
⚠️ 概念归属验证：grep 命中概念名可能来自 NEWS 文本（研报摘要），必须回看是否落在 SECURITY 概念板块行内（见第3步 grep 验证规则）

## 推送方法（企业微信 webhook）

用 Python urllib + json.dumps 最稳（避免 curl 引号/emoji 转义地狱）：

```python
import json, urllib.request
WEBHOOK = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<KEY>"
content = "..."   # 见下方推送精简模板
data = {"msgtype": "markdown", "markdown": {"content": content}}
req = urllib.request.Request(WEBHOOK, data=json.dumps(data).encode("utf-8"), headers={"Content-Type": "application/json"})
print(urllib.request.urlopen(req, timeout=15).read().decode())   # 必须返回 {"errcode":0,"errmsg":"ok"}
```

**文件化推送变体（推荐批量场景）**：先把每条消息 write_file 成 `/tmp/qa/msg_<code>.txt`，再写一个通用脚本只读文件并 POST：
```bash
python3 /tmp/qa/push_wecom.py /tmp/qa/msg_<code>.txt
```
好处：推送前可先 read_file 校验消息内容（防串扰）；消息与推送解耦、方便留档。脚本是每会话临时工具，放 /tmp 即可不用入库。
- ⚠️ **同日多 run 消息文件冲突（2026-09-25 实战）**：/tmp/qa 已有早 run 的 `msg_<code>.txt` 时，本次用**独立前缀**（推荐带日期 `msg_YYYYMMDD_<code>.txt`，如 `msg_20260928_sz002222.txt`；同日再 run 则递增 `msg2_`、`msg3_`）落盘，避免误读/误推旧草稿；推送脚本每次从新文件读取，勿串文件。压缩恢复场景虽可复用磁盘 msg，但仅限"同一次任务中途重启"，跨 run/换数据时点必须重写。
- ⚠️ **长中文 markdown 消息优先 write_file 直写文件**：不要在 execute_code 里用三重引号大字符串拼消息（沙箱解析大段中文+emoji 曾报 `unterminated triple-quoted string` 直接语法错）；先逐条 write_file 落盘（也便于 read_file 校验），再统一循环 push_wecom.py。

### 推送内容精简模板（每条独立，字段比完整报告短）

- 标题：`📊 <名称>（<code>）快速分析 — <日期>收盘`
- 【持仓信息】成本价:open_cost | 仓位:市值/50万 | 建仓日期
- 现价/今日涨跌/盈亏/量比/换手/市值/PE 一行
- **结构定位**（第5步结论：前高/前低/箱体/关键节点/当前位置阶段）
- **生命周期**（周线1年）：T1/T2/T3/T4/R1/R2/R3 阶段 + 关键一句（如"周线多头+MACD零轴上"）+ 与主线共振（顺风/双过热/双退潮/掉队/独立行情）
- **市场风格修正**：<档位>+市场<小/大/均衡>盘占优 → 顺/逆风格；市场<弱势/震荡/强势> → 降/中性/提积极度（数据截至<日期>）
- **资金面**：量价主信号 → 主力净流入仅背离 → 真实主力核实（龙虎榜机构席位/大宗折溢价/两融变化，无记录标注"无龙虎榜/大宗记录"）

## 推送前数据校验 + 错误更正协议

**推送前校验（必做）：**
1. 每条消息推送前，用腾讯 API 实时行情抽查该股 1~2 个关键字段（现价/涨跌），与消息内容比对；成本价与 MySQL `open_cost` 比对
2. 一键校验法（execute_code 内）：`实时价 == 消息价` 且 `消息价 × 数量 ≈ 仓位市值`（数量/现价/市值三者严重不自洽 = 数据串扰，禁止推送）
3. 多股循环推送时，每推完一条立即核对 errcode，并抽查下一条消息的行情数字是否还是上一只股票的值（串扰典型症状：价格张冠李戴）

**腾讯 API 一键校验**（gbk 解码 + 字段索引）：
```python
import urllib.request, re
url = "http://qt.gtimg.cn/q=" + ",".join(codes)  # codes 全部小写，逗号拼接多股一次查
raw = urllib.request.urlopen(urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"}), timeout=15).read().decode("gbk", errors="ignore")
for code in codes:
    m = re.search(re.escape(code) + r'="([^"]+)"', raw)
    f = m.group(1).split("~")
    price = float(f[3])      # f[3]=现价, f[1]=名称, f[32]=涨跌%
    ok = abs(price - batch_price[code]) / batch_price[code] < 0.005   # 盘中相对容差 ±0.5%
    # 超阈值时先看三点自洽（名称/代码/数量×现价≈持仓市值）：自洽=正常时间差，用腾讯API最新价更新报告价；只有价格张冠李戴（明显偏离+名称对不上）才算串扰
    # 收盘后跑可用绝对阈值 <0.01
```
⚠️ 必须 gbk 解码（否则中文名乱码）；量比一律以 batch SECURITY 区块的"量比"字段为准，不取腾讯接口字段。

**不同执行时点的标题规则（以实际数据时间为准，勿机械照抄任务模板时间）：**
- **休市日判定法（task 模板写"盘中"但疑似节假日时必做）**：腾讯API批量拉股+指数（含 sh000001），看 `f[30]` 时间戳字段——若全部返回**上一交易日**的 `YYYYMMDDHHMMSS`（如 20260924161500），且所有个股现价==昨收→ 确认为休市日（节假日/周末），按休市规则标注"数据截至 <上一交易日> 收盘"；f[30] 为当日交易时间戳才可写"盘中"。
- **收盘后模板遇节假日（2026-09-25 中秋休市实战）**：任务模板写"当日收盘"但当天是节假日（中秋/国庆等）时，**21:00 全新 fetch 的数据仍全部返回上一交易日时间戳（所有个股+指数 f[30]==上一交易日，如 20260924161500），这就是休市确认——勿反复重拉/怀疑数据源**。交叉验证：quotes K线最后一行日期 == SECURITY 最新价日期 == industry_themes MAX(theme_date)（本次三者均为 09-24）。标题统一"数据截至 <上一交易日> 收盘"，可附"（今日<节日>休市）"；不写"当日收盘"、不写实时表述。主线/板块文件**一律用 MAX(theme_date) 对应日期**（09-24 → plate_20260924.md），即使当天更新的 plate（如 plate_20260925.md）已存在也**不采用**（主线推理未更新，板块文件须与主线同日对齐）。
- 休市日（周末/节假日）：数据源返回最近交易日收盘数据 → 标题标注"数据截至 <上一交易日> 收盘"，不写"盘中"、不写"今日盘中最高/最低"这类实时表述
- 午间休市（11:30-13:00）：返回上午收盘数据（当日K线未收盘、缠论多为待确认）→ 标题标注"午间（上午收盘）"
- 盘中（交易日 14:00）：SECURITY/腾讯API 半日实时值，quotes 当日K线未收盘、缠论"待确认"是正常现象 → 标题按任务要求写"14:00盘中"（或按实际拉取时刻写"14:40盘中"），建议措辞加"盘中数据未收盘（收在X上方才确认有效突破）"，量比/换手为盘中折算值注明；结构定位仍以已收盘完整K线为主、当日盘中K线为辅
- ⚠️ **盘中龙虎榜方向矛盾判定（2026-09-29 实战）**：lhb 头部行情行日期=查询日、但 Reason 与查询日涨跌方向矛盾时（如福晶 9/29 查询日 +1.15% 却返回"日跌幅偏离值达7%"），该榜归属最近一次真实触发日（9/28 -9.33% 跌停潮日），按触发日归因资金方向，勿算在查询日头上——方向矛盾即旧榜的强信号，若该股近期无其他可比触发日则盘中年内新榜需按"盘中新榜量级松弛补丁"校验
- ⚠️ **大宗价格锚定前收盘价的处理（2026-09-29 实战）**：TurnoverPrice 不在查询日K线区间、但恰好等于数日前某收盘价（如沪电 124.05 = 9/24 收盘价），判定为按前收盘定价的协议成交/披露滞后（T+1 或假期顺延），不满足"当日新成交三条件"的③ → 不写入当日资金面，但机构接货/平价折价信息可标注为"历史记录（披露日X，机构平价接货，偏正面参考）"
- 盘中龙虎榜可当日返回（当日触发上榜条件的股票盘中即公布），返回"当日无龙虎榜数据"=当日尚未触发，属正常非数据缺失；当日晚间榜单可能更新更多席位，盘中以已披露席位为准

**已错误推送的更正协议：**
- 立即推送 ⚠️**【数据更正】**消息：标题前缀 `⚠️ 【数据更正】<名称>（<code>）快速分析 — <时间>`，正文首行写明"更正说明：此前推送的现价/成本数据有误，以本条为准"，再发完整正确版报告
- 更正消息后补推汇总表时，汇总表用**更正后的真实现价**重算，不要沿用错误数字
- 推送确认依旧要求 `{"errcode":0,"errmsg":"ok"}`

## 关键陷阱

1. **数据接口统一用 finance_wrapper.py**（mcporter 已不可用）
2. **代码必须小写**（腾讯 API 大小写敏感，大写返回空）
3. **quotes 必须 standalone 调用**：batch 里虽可带 quotes 但缠论完整性以 standalone 为准（skill 内统一 standalone）
4. **持仓成本价用 open_cost（首仓价）**，不用 open_price（均摊成本）；差异大时先做区间校验（第2步）
5. **过滤 Pydantic 警告仅 4b 适用**（`grep -v PydanticDeprecated | grep -v "class BaseTool"`），否则污染解析；4c/4d/4e 无 Pydantic 输出，勿过滤（见第4步说明）
6. **主力净流入已降级为辅助指标**：fund_flow 按订单规模分档在算法拆单/量化高频下严重失真，且北向实时数据停披后信号走弱。**禁止把"主力净流入为正/负"当独立买卖依据**，仅用于背离提示；真实主力动向看龙虎榜(lhb)/大宗(blocktrade)/两融(margintrade)；日常判断以量价结构为主
   - **资金共振升级提示**：主力持续/显著净流出（相对该股自身近期水平与成交规模，如连续多日流出、排名市场垫底、占成交额比例高且伴随放量下跌/滞涨）时，量价与资金共振 → 可作为减仓决策的参考信号；"排名垫底+连续多日流出"本身即可触发，不必等放量；**缩量横盘+主力持续流出排名垫底 = 横盘派发特征，同属主信号**。小额流出=背离提示忽略，显著流出=必须提示风险
   - **统计口径**：`分析说明`里的"连续N日净流出"**已包含当日数据**，判定时直接采信 N，勿因与可见历史行差1天怀疑数据
   - **当日主力净流入计算法**：batch FUND_FLOW 历史行只覆盖近10日（不含查询日），用"分析说明：今日净流入较近5日净流入均值增减 X 万元"反推 **当日主力净流入 ≈ mean(近5日历史行) + X**（万元）——判定资金面显著流出时用该公式算当日值，勿因历史行缺当日行漏判；⚠️ 同一交易日不同时点增量会刷新（资金变动实时更新），**当日值一律按当次查询的分析说明重算**，勿沿用同日前次/跨会话数字
   - **FUND_FLOW 区块格式版本差异（2026-09-28 实测）**：新版 finance_wrapper batch 的 FUND_FLOW 区块**只有当日指标表**（主力净流入/超大单/大单/中单/小单 + 占成交额比 + 市场排名 + 占流通市值比例），**无历史10日行、无分析说明**——当日主力净流入直接采信指标表首行"主力净流入"值（如 `主力净流入 | -9203.40万元`），勿因找不到分析说明/历史行误判数据缺失或漏判当日流出；旧版才有历史行+分析说明（用反推法）。两版兼容：拿到直接值用直接值，拿到历史行+分析说明用反推法，报告口径注明"主力净流入X万（占成交Y%）"即可
7. **新闻免责声明/宣传话术**提取核心事实即可，不要照抄
8. **主线匹配连 portfolio 库**（wish 用户），不是 llm_stock；概念匹配必须精确字符串比对，近似≠命中；ended 状态主线即使命中也无操作意义（但 ended **非终点**，可被重新激活——归属结论必须每日按当日 MAX(theme_date) 重新比对）
9. **16:00 前 / 隔夜分析**：主线可能只有当日或昨日记录——用 MAX(theme_date) 并标注实际主线日期；板块文件也用同一日期的文件
10. **grep 必须用 `-E "\|<代码> \|"` 管道符精确匹配**——裸 grep 代码会同时命中表格2成分股行（该行最后列是股票列表非概念），解析必错
11. **必须做结构定位回溯（第5步），禁止只凭近10-15日K线判断位置**——近1个月数据会漏掉前高/箱体/突破节点；quotes 拉取区间不少于3个月；"缩量回踩不破突破位"是健康信号，不是走弱
12. **突破≠确认**：单日放量突破前高只是"突破"；真正可操作的是"突破→缩量回踩不破→再放量上攻"三步走完（回踩确认完成）
13. **westock-data 必须 node 全路径调用**：`node /home/agentuser/.hermes/skills/westock-data/scripts/index.js <cmd> <code>`（cmd: lhb/blocktrade/margintrade）；调用后必须确认得到真实数据或"当日无XX数据"，出现 command not found / exit 127 立即换 node 全路径重试，**禁止**标注"数据源缺失未核实"跳过
14. **批量推送前必须校验行情数字**：推送前用腾讯 API 实时价抽查 + 校验"数量×现价≈持仓市值"三点自洽；已错推的立即发 ⚠️【数据更正】消息（见"推送前数据校验 + 错误更正协议"一节），汇总表用更正后真实现价重算
15. **周线数据用 4d 脚本（lifecycle_weekly.py）**：直连腾讯 ktype=week qfq 接口（与 quotes 同源）；volume 已换算万手，MA/MACD/RSI 为脚本按标准公式计算（EMA平滑/Wilder RSI）；周线最新一根 = 最近交易日所在周（周末/节假日拉取时标题日期沿用现有休市判定法）；脚本为 python 直连，**无 Pydantic 警告输出**，无需过滤前两行
16. **周线数据不足20周（次新股）**：生命周期标注"⚠️ 周线数据不足，仅依赖日线大结构"并回退判断，**禁止强行判定阶段**；脚本顶背离辅助仅在价格贴近52周高点（距高≤10%）时输出，深跌回调场景无输出属正常（非数据缺失）
17. **市场状态文件取最近一期**：`ls -t /home/agentuser/data/定时任务打包/data/market_state_*.md | head -1`；读"状态/风格/结构结论 + 策略含义"；数据日期≠分析日 → 标注"市场状态数据截至 <日期>"（与主线日期口径一致）；文件缺失处理见"市场风格结构修正"小节（跳过环境修正，禁止臆测大盘环境）
18. **市值分档用 security 总市值**（亿元），不是流通市值；档位映射指数风格（≥500亿=沪深300风格 / 100~500亿=中证500 / <100亿=中证2000）；市场风格匹配只在"大小盘结论×市值档位"层面做，成长/价值维度不强行套用到个股；**环境修正只调倾向不翻盘**——个股自身判断（结构/生命周期/量价）是主体，市场风格仅在结论措辞偏移层面生效
19. **判断 quotes 最新K线日期禁止用 `grep -oE "^\| YYYY-..-.. \|" | tail -1`（2026-10-12 实战踩坑）**：该模式会同时命中文件**后半部的缠论分型/笔/中枢行**（形如 `| 2026-09-22 | 顶分型 | 69.82 | ... |`），`tail -1` 取到的是分型日期而非K线末行——实测福晶 quotes 返回 09-22（缠论顶分型），实际最新K线为 10-12，会把新鲜数据误判为陈旧、甚至触发不必要的重拉 fetch。**正确做法**：① 读文件内 `**最新MA数据摘要（YYYY-MM-DD）：**` 行取权威最新日期（最稳）；② 用 parse_qa.py（强制 14 列过滤，天然排除分型/笔/中枢行）；③ 或 `grep -c "| <当日日期> |"`（收盘后返回1）。⚠️ 同理，"`tail -3 <code>_quotes.txt` 看最后K线日期"的说法也不可靠——文件末尾是"中枢表 + `- 数据来源: 腾讯财经`"行，不是K线行；要取末行K线须先按 14 列过滤
