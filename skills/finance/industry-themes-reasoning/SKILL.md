# 产业主线推理聚合（每日16:00）

替代旧 `~/data/定时任务打包/scripts/update_industry_themes.py`。核心差异：
- **禁止硬编码 THEME_MAP 查表** — 概念→产业链归属、主线命名全部由 Agent 推理生产
- 不写 python 脚本 — 数据读取/写库用 read_file + mysql CLI（仅允许生成 SQL 文本）
- 状态判定用**三维决策树**（H热度×T技术×F基本面，见步骤3，与 16:30 fetch_trend 同款逻辑）— 策略参数，非硬编码映射

## 输入

1. 当日板块统计文件：`/home/agentuser/data/定时任务打包/data/plate/plate_YYYYMMDD.md`（**必须存在且当日 15:30 后生成**，缺失一律中止，禁止用昨日文件回退，见第 0 步）
2. 上一条主线记录（迁移基准，含断档/周末承继）：先查最近 10 个交易日的全部记录，取每个主线的**最近一条**（间隔 ≤ 10 自然日才可迁移，见步骤3）。SQL 示例：`SELECT * FROM industry_themes WHERE theme_date <= '<今日>' AND is_legacy = 0 ORDER BY theme_date DESC LIMIT 50` 后按 theme_name 去重取最近（**P4 后必须过滤 is_legacy=1**——废弃宽链记录不参与迁移基准，否则会把 10-09 旧宽链当父母链误迁移）

## 数据库

- 连接：`mysql -u wish -p<DB_PASSWORD> portfolio`（wish 对 portfolio 有 ALL PRIVILEGES）
- 表：`industry_themes`（id, theme_name, theme_date, status, consecutive_days, related_sectors JSON, peak_count, peak_date, created_at, break_level TINYINT, advice_signal VARCHAR(20), score_heat TINYINT, score_tech TINYINT, score_fund TINYINT, **parent_theme VARCHAR(100), related_chains TEXT, signal_peak INT**）
  - `parent_theme` = 链族名（P2 D4，19:30 归约展示）；`related_chains` = 次属链 JSON（B1 披露 + B2 半票）；`signal_peak` = 当日信号口径峰值（与历史 peak_count 分离，C5 晋升/信号层监控用）
  - `score_heat` / `score_tech` / `score_fund` = **三维评分每日快照（0~3）**：H 热度由 16:00 写当日快照；T 技术 16:00 写初判占位、16:30 修正覆盖；F 基本面 16:00 写 theme_fundamentals 当日生效值。报告/下游单表可查，历史可追溯
  - **H 热度 16:30 修正**：fetch_trend.py 按 sector_rank_daily 最近落库日（=上一交易日，天然"次日生效"）的全A位次 rank_daily 修正 score_heat——主线 sectors 取最优（最小）位次，≤25（前20%）→ +1、>62（后50%）→ -1，cap 0~3（设计 3.1 L36）；修正后 H 参与 16:30 决策树重算，score_heat 列同步写回
  - `break_level` / `advice_signal` 两列由 **16:30 fetch_trend.py 技术确认回填**（0未破/1破MA5/2破MA5+MA10/3破MA20；建议=进攻/防守/持有/中性/博弈/谨慎/观察）；**16:00 推理不写**，保持默认 0/NULL。**theme_advice 分级建议**：bl≥2 → 防守；bl1 → 谨慎（active/peaking 同语义"跌破MA5减仓观察"）；bl0 按 trend（上涨/反弹→进攻、调整/不明→中性、下跌→防守；peaking+bl0→持有）。16:45 龙头分析只分析 `status IN ('active','peaking') AND break_level<2` 的主线（技术破位降级不产 A级）。**16:30 落库顺序**：三维重算（status/score_tech 双向修正）→ 场景门控层 R1/R2（只改 status，详见步骤3 门控段）→ **建议以门控后终态生成**（theme_advice 用最终 status，不用初判）→ 回填
  - `consecutive_days` = **连续上榜天数**：今日上榜>0 且上一条同名记录连续天数>0 且间隔≤10自然日 → +1；否则上榜日=1、未上榜日=0。与状态迁移解耦（状态由三维决策树决定，见步骤3），仅作为生命周期展示/持续性评分依据
- 表：`theme_constituents`（P2 C1 成分基线，**指数合成源**）——(theme_name, stock_code) 主键，primary_chain=主属链，related_chains=次属链 JSON，biz_evidence=主营证据，biz_report_date=主营报告期，add_date/remove_date/is_current 管理生命周期；16:00 写子链时**同步初始化/更新成分基线**（upsert 幂等：同 code 再写行数不变），主营不变不重推（防 LLM 漂移）
- 表：`theme_constituent_changes`（P2 C3 变更日志）——theme/stock/change_type(add/remove)/reason(白名单四类：主营变更/新上市/退市/晋升)/evidence/change_date/rollback_snapshot；**成分变更仅白名单事件触发**，每子链单日 ≤10%、30日 ≤15%，超限冻结 3 日+人工复核
- 表：`theme_fundamentals`（theme_name VARCHAR(50) PK, fund_score TINYINT 0-3, logic_type VARCHAR(20), logic_desc VARCHAR(255), eval_date DATE, updated_at TIMESTAMP）——**F 基本面分权威源**，低频更新：16:00 推理先查表拿 F，仅当产业逻辑实质变化（政策出台/景气拐点/概念证伪）才 UPDATE，无每日重评 = 无漂移源；PE 只做参考不入判据
- **写库 JSON 格式（唯一权威定义）**：`{"concepts": [...], "major_concept": "...", "sectors": [{"name": "煤炭开采", "code": "pt01801951"}, {"name": "炼化及贸易", "code": "pt01801963"}, ...]}`
  - `sectors` **必填**：下游 16:30 fetch_trend.py 按行业板块拉全量成分股合成主线指数；缺 sectors 的旧格式（仅 concepts+major_concept，fetch_trend 只能映射概念TOP10成分股）覆盖不全，已弃用
  - **P2 指数合成源切换（fetch_trend.py `get_theme_stocks`）**：成分基线优先（`theme_constituents` 中 primary_chain=该子链的股票）→ sectors 回退（板块全量成分股）→ concepts 回退（表格1）；成分基线空（存量未初始化期）自动回退旧逻辑，报告标注「成分基线模式 / sectors回退模式」
- 行业板块代码来源：腾讯 `https://proxy.finance.qq.com/cgi/cgi-bin/rank/pt/getRank?board_type=hy2&sort_type=PriceRatioD20&direct=down&selector=not_in_market%3Dgn_fg&count=200` 返回**全量124个行业板块名称+pt代码**（⚠️ 路径必须是 `/rank/pt/getRank`，写成 `/rank/hs/getRank` 报 code=12 service invalid；必须带 sort_type 参数，否则报 code=51 invalid CommonReq.SortType）；成分股用 `https://proxy.finance.qq.com/cgi/cgi-bin/rank/hs/getBoardRankList?board_code=<pt代码>&sort_type=priceRatio&direct=down&count=200`（注意此处是 `/rank/hs/`，与行业排行 `/rank/pt/` 相反）返回该行业板块**全量成分股**（炼化及贸易30只/煤炭开采26只/农化制品59只/航运港口34只/铁路公路33只/航空机场12只/国有大行6只/股份行9只）
  - **响应格式实测（2026-09-29）**：getRank 板块列表字段是 `code`/`name`（不是 board_code/board_name）；getBoardRankList 成分股在 `data.rank_list`（不是 board_rank_list）；**count 参数上限 200，传 300 静默返回空 list（code=0 但 rank_list=[]，极易误判"板块无成分"）**——测规模务必 count=200 且校验 len>0，为 0 时先查响应结构再下结论

## 执行步骤

### 0. 前置检查（硬性门槛，先做再做其他）

```bash
ls -la --time-style=full-iso /home/agentuser/data/定时任务打包/data/plate/plate_$(date +%Y%m%d).md
```

- **文件不存在** → **立即中止**：不推理、不写库、不生成主线报告

  - **禁止**用昨日文件推理今日主线，**禁止**写任何今日 industry_themes 记录（回退会让当日主线变成昨日冻结数据假续期，污染 16:30 fetch_trend 下游）
- **文件存在但 mtime 早于今日 15:30**（说明是昨日旧文件被复用）→ 同样视为缺失，中止
- 文件存在且新鲜 → 继续第 1 步

### 1. 读取板块文件

- read_file 读 `data/plate/plate_YYYYMMDD.md`
- 表格1：`## 表格1：概念板块 TOP10 成分股汇总`，列 `股票名称 | 代码 | 最新价 | 当日涨跌 | 5日涨跌 | 20日涨跌 | 所属概念板块`（概念用`、`分隔，多概念股票是共现关键）
- 表格2：`## 表格2：二级行业板块统计`，列 `板块名称 | 板块代码(pt开头) | 出现次数 | 股票列表`
- **解析/统计用参考脚本**：`scripts/parse_plate.py`（本 skill 自带）——表格1/2 解析（含列位陷阱修正）、概念频次、簇统计、簇→板块交集分布（R1.2）、R1.3 成分规模实测。daily 读取用 plain open()，勿重复依赖 hermes read_file（同会话返回占位符）。按当日概念标签修改脚本内 CLUSTERS 定义后运行

### 1.5 池外新链确认（18:30 new_chain 回接，设计 v2 3.5）

> 18:30 池外主营推导可能产出「新链:主营共性短名」（Agent 无法归入现有链时），标注 new_chain 待主线侧确认。**本环节（16:00）是唯一确认入口**，次日开盘前闭环；确认前该链池外候选正常输出但标注「新链待主线确认」。

1. **读取前一日池外推导结果**：查最近一个交易日的 `data/pool_derivation_result_YYYYMMDD.json`（缺失/无新链 → 跳过本节）：
   - 提取 `boards[].derived_theme` 以「新链:」开头的链名（去重）
   - 同时读对应 `outside_pool_themes_YYYYMMDD.json` 确认该链是否已产出候选（track_level）
2. **确认判定**（对照今日板块统计文件）：新链覆盖板块在今日表格2 上榜 ≥3 只，或表格1 概念共现可支撑产业链语义 → **纳入今日候选**：该链进入本步骤2 推理聚合候选池（走 2.1 成色三层过滤，写库按新主线流程）；今日无支撑 → **不纳入**：报告「新链未获确认」小节逐条列出（链名、覆盖板块、未确认原因），不写库
3. **命名规范**：确认纳入后去掉「新链:」前缀用主营共性短名建链（如「新链:电池产业链」→ 电池产业链），并在报告标注「🔄 新链确认：源自 18:30 池外推导 M 日，今日纳入」
4. **披露**：报告「明日关键观察」中给每条待确认新链写验收线（如"覆盖板块上榜≥N 才纳入"），次日 16:00 再看

### 1.6 归属复核闭环 + 独立成链机制（16:20 守卫审计回接）

> 16:20 `guard_theme_sectors.py` 产出 `portfolio.sector_link_audit`（语义一致性审计，**只告警不写库**）。本环节是唯一消费入口，次日 16:00 消费**前一交易日**的审计。

1. **读前日审计**：`SELECT trade_date, link_name, sector_name, verdict, suggestion FROM sector_link_audit WHERE trade_date='<前一交易日>'`（缺失 → 跳过本节）
2. **逐条复核**（按 verdict）：
   - `insufficient_coverage`（板块成分在 theme_constituents 覆盖不足）→ **不得据以增删板块**；报告披露「需补全成分基线」
   - `semantic_mismatch`（板块语义主导链存在、但该链未收录本板块）→ 复核后将该板块**补入其语义主导链**或从现链移出
   - `orphan_chain_candidate`（语义主导链不属任何现有链族）→ 走第 3 条独立成链判定
3. **独立成链 = 通用机制（非特例）**：当某板块的主导语义簇不隶属任何现有链族，且该语义簇在今日板块统计中有支撑（≥2 板块或成规模成分）→ **独立成链**，命名 = 板块名 + 语义簇。实例：军工-航空装备Ⅱ 的主导语义=航空制造，不隶属「军工」链族 → 建立「航空装备产业链」
4. **覆盖不足优先修复**：`insufficient_coverage` 条目须先补全 `theme_constituents`（F10 主营）再复核，**禁止在覆盖不足时判定归属**（count-based 判据在基线不完整时必然误判）
5. **披露**：报告新增「归属复核」小节，逐条列出前日审计 verdict → 本轮处置（采纳 / 待补全 / 独立成链）

### 2. 推理聚合主线（P2 五步聚合，核心，输出：候选子链）

> P2 口径：聚合键从「概念标签」改为「主营语义」——概念共现只圈候选范围（信号层），**子链身份与命名由主营归因决定（成分层）**；**板块 sectors 归属同样由主营语义决定，禁止用「成分交集计数/纯度/覆盖率」判定**（概念范畴仅用于圈定候选与代表股映射）。子链粒度对齐池外（≥2板块+主营同质，单板块进观察线）。参考设计 `20261010_主线聚合下钻细化设计.md` §3.2。

**五步聚合（按序执行，缺一不可）**：

**Step 1 候选池生成（宽簇，圈范围不命名）**
- 对表格1全部概念标签做**共现聚类**（Agent 自己算，不写脚本）：同一股票带多个概念 = 共现证据；共现≥2次归同一宽簇
- 输出宽簇（含 concepts、去重股票 set、平均5日涨跌幅）——**此时不命名产业链**（命名等主营归因后）

**Step 2 主营归因（每股主属链，核心）**
- 对宽簇内**全部去重股票**批量取主营：读 `data/business_cache/<code>.json`（业务缓存，字段 code/name/yw/report_date/products）
  - 缓存未命中（新面孔）→ 用 `scripts/prepare_pool_derivation.py --fetch-codes <code,...>` 增量补拉（≤100 只/日保护；结果仍缺 → 该股标「主营未知」）
  - 18:30 池外主营推导已消费同缓存（D1 统一语义层），16:00 为**次日消费+增量**
- 每股按主营原文（yw）判定**主属链**（primary_chain，证据=主营原文摘录）+ 次属链（related_chains，若有）；主营未知/跨多业不硬归 → **独立股池**（B4，月级复核，不入链指数/建池）
- 主营相同或高度同质的股票聚为**子链候选**（如主营=涤纶/氨纶/钾肥 → 化工-化纤链）

**Step 3 子链命名（命名空间与池外统一）**
- 命名格式：`<链族>-<子链名>链`（如 化工-煤化链 / 化工-化纤链）；池外 18:30 已有权威名（化工-化学纤维链）**优先沿用**，禁止同链异名
- 链族层 = parent_theme（如 化工），19:30 归约展示用；子链名是 industry_themes 主记录单元
- **沿用 theme_fundamentals 既有链名**保持下游连续性（金融科技产业链等单链族场景）；major_concept 取当日最强分支
- 禁止编造不存在概念/主营；主营证据非空才能命名

**Step 4 板块载体验证**
- 子链候选反查表格2/腾讯接口：覆盖的二级行业板块 sectors（下游 fetch_trend 依赖）
  - **覆盖完整性（R1.2）**：按子链**全部**主营归因股的板块分布反查，覆盖全部主要板块；**桥接股**（同股带主线主营 + 属另一板块）强制纳入
  - **规模克制已退役（R1.3 去判据化）**：原「主营股数×5 / ×3 或 300 只」上限为**固定数量判据**，已删除。板块纳入改由**语义一致性**裁决——语义不符的巨量外围板块天然被排除（规模上限成为冗余），语义一致的板块即使规模大也照常纳入（下游按 `theme_constituents` 成分基线取数）
  - **禁止编造 pt 代码**（必须来自表格2或腾讯接口实测）
- **块主载体 2~3 板块**：单板块 → 观察线（对齐池外 A1，不是硬门槛淘汰）

**Step 5 身份判定（防换血核心）**
- **链身份 = 核心 sectors（≥2板块）+ major_logic（theme_fundamentals 主营描述）**
- 概念集变化但核心 sectors 稳定 → **非换血**：刷新概念信号，成分不动
- 核心 sectors 漂移（交集<1/2）且 **连续 2 日确认** → 旧链闭合（ended → 17:30 监控池），新链按新识别
- major_logic 实质变化（主营变更）→ 旧链闭合，新链重识别
- **删除旧规则**："概念集换血仍走迁移路径承继链名"（P2 防换血，化工 sectors 漂移 4→1 即此坑）
- **股数门槛统一由 2.1 硬门槛把关**（此处只统计 stock_count 与主营归因覆盖）

### 2.1 主线成色过滤（对齐池外 track_level）⭐ 写库前强制

> 目的：拦截「口含烟 / 头盔 / 3D打印」这类概念标签伪影子链。判定为伪 → 降级「观察线」，**只进报告不写库**。
> 适用范围：**新识别候选子链**走完整三层；**迁移子链**只过第1层的结构性硬门槛（第2/3条），不过则强制转 ended。
> P2 口径：硬门槛对齐池外（板块≥2 + 主营证据非空），不再以概念股数 15 为门槛（子链粒度更细，主营归因是身份证据）。

**第1层：硬门槛（一票否决，任一不过 → 观察线，不写库）**

| # | 门槛 | 判据 |
|---|------|------|
| 1 | 主营证据非空 | 子链候选每板块代表股主营可归因（yw 非空）；全部未知 → 是"标签现象"而非"行业现象" |
| 2 | 可映射 ≥2 个二级行业板块 | 无 sectors 或仅1个 → 观察线（口含烟即此：6股映射不到任何板块）——**单板块进观察线，不是硬淘汰**（对齐池外 A1） |
| 3 | 板块间须有产业上下游/同级产业链关系 | 无关板块并集（如 塑料+摩托车）→ 否（头盔即此） |

**第2层：成色评分（5维 × 0~3分，满分15，准入线 ≥9）**

| 维度 | 3分 | 2分 | 1分 | 0分 |
|:----|:---:|:---:|:---:|:---:|
| 产业纵深 | ≥3个同链板块 | 2个同链板块 | 仅1个板块 | 板块无关/无映射 |
| 市值锚 | ≥1000亿 | 300~1000亿 | 100~300亿 | <100亿 |
| 逻辑成色 | 国家战略+政策文件 | 政策性景气周期 | 事件/季节催化 | 纯概念 |
| 龙头质量 | 20日涨幅为正+主业相关+市值≥300亿 | 部分满足 | 蹭概念为主 | 超跌反弹 |
| 持续性 | 连续≥3天上榜 | 2天 | 首日 | 单日脉冲/当日未上榜 |

- 市值锚 = 子链内最大流通市值：用 finance_plugin/westock 查前3大市值股核实，或按 Agent 产业常识估量级（量级判断即可，±50%可接受，评分为区间制）
- 龙头质量看表格1「所属概念板块」列：股票带多个概念且该概念非其主业 → 蹭概念（如 拓斯达=华为机器人+头盔、银禧科技=电子树脂+头盔），子链内蹭概念占比过半 → 龙头质量≤1分
- **持续性评分对齐 consecutive_days（连续上榜天数）**：查询该子链在 industry_themes 历史记录中的连续上榜天数（按步骤3口径），≥3天=3分、2天=2分、首日=1分、当日未上榜=0分——不用"观察线待了几天"等模糊表述
- **逻辑成色维度评分 = F 基本面分（fund_score）**：该维度的评分即未来写库的 score_fund 值，落库 `theme_fundamentals` 表（低频更新，见数据库节/步骤3），不逐日重评

**第3层：生命周期确认（首日 → 观察线）**

- 新识别候选**首日**：评分再高也先进「观察线」（报告记录分数+原因，不写库）
- **转正条件**：连续2天及以上维持（读**最近一份**报告 industry_themes_*.md 的观察线区，确认该候选曾在观察线；断档/周末间隔 ≤ 10 自然日可承继）+ 硬门槛全过 + 评分≥9 → 写库转正，consecutive_days=1 起算
- **爆发例外**：硬门槛全过 且（单日覆盖≥40 或 评分≥13）→ 可当日写库，报告标注「新爆发」（对齐基金框架"爆发跳过试探期"）
  - **爆发例外只豁免"首日观察期"，不豁免三维判定与峰值规则**：若历史有同名记录（间隔≤10自然日），仍走迁移路径——状态按步骤3三维判定、peak_count 沿用 max(历史,今日)。「新识别」路径仅限真正无历史记录或间隔>10自然日的主线

**迁移子链结构性淘汰（清存量垃圾）**

- 迁移子链（**最近一条记录存在且间隔 ≤ 10 自然日**）只过第1层硬门槛第2/3条（结构性门槛），不过 → 今日直接 INSERT status='ended'，报告标注「成色结构性淘汰」+ 原因
- 股数门槛**不对迁移子链生效**：退潮期子链股数可自然回落；银行/运营商类行业股数天然少（六大行+股份行仅10只）是行业约束非伪信号，靠板块纵深+市值锚通过评分
- 评分不重算迁移子链（三维判定管退潮，见步骤3）

### 2.2 子链数量上限策略（每链族 ≤ 8 条，按 parent_theme 计）

上限作用域 = **单个链族（parent_theme）**，跨链族不互相挤出；单链族（银行/运营商等 parent=自身）不受限；全局不设安全阀（设计 §3.4 / 确认清单 A2，2026-10-12 修正）

按以下顺序收敛：

1. **链族归约仅展示层**：同链族子链（如 化工-煤化链/化工-化纤链/化工-燃气管网链）在 19:30 报告归约为「化工」链族展示（parent_theme GROUP BY），**16:00 记录与跟踪层不做大类归并**——子链是独立记录单元
2. **族内收敛**：按 parent_theme 分组，**族内**候选 >8 条 → 族内按 2.1 第2层成色评分降序取前 8 条写库（同分按 stock_count），其余族内末位降级为「观察线 · 族内挤出」区（仅写报告，不写库），标注 `cap_exceed`——日常最大族 7 条（10-09 化工）→ **常规零触发**，仅某族单日候选 ≥9 条才生效
   - **族内挤出区报告格式**（供 17:30 cap_exceed 登记留痕）：`| 链族 | 族内候选数 | 上限 | 挤出链 | 族内评分 | 挤出原因 |`
   - **禁止跨族挤出**：某族爆发（如 media 单日 5 席）不得挤掉他族迁移链；迁移链只要族内候选 <8 就必须写库（走三维判定）
3. 子链名取主营最显著产业名；concepts 保留（下游 fetch_trend 按 concepts/成分基线过滤）；stock_count/平均涨幅按主营归因后的股票集合重算（可用 python 解析表格1精确计算）

### 3. 状态迁移（旧主线，16:00 三维初判）

对每条**上一条记录存在的主线**（间隔 ≤ 10 自然日，含断档/周末恢复）计算今日上榜数 today_peak：
- 概念维度优先：该主线 concepts 中所有概念覆盖股票的**并集数**
- 板块维度回退：related_sectors 中板块代码在表格2的 count 最大值

**三维评分**（写库时落 `score_heat` / `score_tech` / `score_fund` 三列）：

**H 热度分（score_heat，当日快照）**
- today_peak/峰值 ≥50% → 3；30~50% → 2；10~30% → 1；<10% → 0
- 峰值 = max(历史 peak_count, today_peak)；创新高时 peak_date=今天

**F 基本面分（score_fund，低频）**
- 查 `theme_fundamentals` 表取 fund_score（= 2.1 第2层逻辑成色评分 0~3）为当日生效值
- 无记录 → 按 2.1 逻辑成色评分 INSERT 初始化；本轮产业逻辑实质变化（政策出台/景气拐点/概念证伪）→ UPDATE；无变化 → 沿用不重评
- **PE 只做参考不入判据**（辅助判断逻辑成色，永不参与任何降级）

**T 技术分（score_tech，16:00 初判占位）**
- 上一条记录 score_tech 有值 → 沿用（16:30 以真实 break_level 重算覆盖）
- 无 score_tech（旧数据）→ 用上一条 break_level 映射 {0:3, 1:2, 2:1, 3:0}；无技术记录（NULL）→ 中性 2

**决策树（唯一权威，与 16:30 fetch_trend.compute_three_dimension 一致，禁两套逻辑）**
```
if T == 0（bl≥3 或破MA60且MA20向下）:
    status = 'ended'          # 技术破坏 → 17:30 监控池 trend_ok 接管（F≥2 可复活）
elif F == 0（纯概念伪主线）:
    status = 'ended'          # 结构性淘汰，不登记监控池（原 2.1 拦截延续）
elif T ≥ 2 and F ≥ 2:
    status = 'active' if H ≥ 1 else 'peaking'   # 热度退坡≠降级，16:45 照常进池
elif T + F ≥ 4:
    status = 'peaking'        # 下限保护观察（如 T=1+F=3 逻辑极强）
elif T == 1:
    status = 'peaking' if H ≥ 1 else 'fading'   # 1天观察窗口；bl=2 次日未修复 → 16:30 正向修正 fading
else:
    status = 'fading'
```
- **state 语义**：active = 主升共振（T≥2&F≥2&H≥1）；peaking = 热度退坡但趋势+逻辑完好（T≥2&F≥2&H=0）或下限保护——**16:45 照常建池精筛**；fading = 技术临界（T=1&H=0）或 F=1 逻辑弱化；ended = 技术破坏（T=0）或逻辑否定（F=0）
- **16:30 修正机制（允许双向）**：16:00 初判写初态后，16:30 fetch_trend 用真实 break_level 重算决策树，**覆盖修正 status/score_tech**（ended→peaking 反向修正允许，银行案例）；T 技术分 = bl 映射 {0:3,1:2,2:1,3:0} 与主线指数 MA 结构（≥MA20且MA20向上=3/≥MA20=2/<MA20但≥MA60=1/<MA60且MA20向下=0，取 min，数据不足宽容）共同决定，T=0 当 bl≥3 或 破MA60且MA20向下（设计 3.1 第一层"或"关系）；H 热度同批叠加全A位次修正后参与重算；score_heat/score_tech 列同步写回。17:30 监控池登记读取**修正后最终 status**，避免 ended 主线程被误登记
- **16:30 附加防线（2026-10-10 落地，T4 0上榜禁反向）**：`fetch_trend.analyze_themes` 在三维判定后、R1/R2 场景门控前调用 `apply_zero_listing_guard`——当三维判定将 ended/fading 反向修正为 active/peaking 时，若该主线所有 sectors 板块在当日表格2（`parse_plate_table2`）上榜合计=0 → **禁止反向，维持原退潮状态**（打印 `└─ 🛑 0上榜禁反向`）。拦截的是"0 关注度主线被 sectors 残留虚高指数拉回"（金融科技 09-07 案例：sectors 残留通信设备，光模块股推高指数致 ended→peaking 误拉回）；有上榜（total>0）才允许反向。**T3 消费侧防线同批落地**：`adjust_heat_by_rank` 新增 `valid_sector_codes` 参数，H 修正位次取数前过滤"板块成分与该链 theme_constituents 交集为空"的残留板块；`fetch_theme_leaders.build_pool` 建池时同样跳过残留板块（交集=0 → `⏭️ 跳过残留板块 XX`，全部跳过则回退 concepts）；写入侧校验工具 `verify_theme_sectors.py` 增加 `--date/--fix`（一致性报告 + 写库剔除残留板块，默认只报告）
- **16:30 场景门控（R1/R2）**：三维判定**之后**、回填写库之前叠加场景门控层，门控后状态为最终落库 status：
  - **R1 大跌日 ended 延迟确认**：报告日上证当日涨幅 ≤ −0.5% 时，三维判定 ended → 降级 fading（观察，不输出强看空/不参与信号）。逻辑：大跌日确认 ended 次日多为超跌反弹，先回踩确认再杀跌。回测 6/6 复现（08-24 医药 + 09-02 五条：金融科技/AI算力/医药/电子材料/有色），避免 4 次杀跌错误
  - **R2 低位升级减速带**：报告日 |上证| ≥ 0.5%（普涨或大跌）时，前一交易日 faded/ended 今日跳升 active → 只升 peaking（不确认强势、不追高）。⚠️ **低触发是预期**：三维判定通常提前数日完成低位升 A（生产库历史 prev 已是 active），"当日跳升"罕见；回测 3 条验证样本来自旧状态机（bak_replay）升级污染视角，生产库新状态机下不复现，实证样本待下周积累复核
  - 触发数据：上证当日涨跌幅 `fetch_sh_index_pct()`（sh000001 K线最新两根；失败 → 门控整体跳过）、prev_status `fetch_prev_status()`（industry_themes 前一日 status，theme_date<当日最大日期；失败 → R2 不触发）。实现：fetch_trend.py `apply_scene_gate()`，开关 `SCENE_GATE_ENABLED`
  - **不对技术分生效**：score_tech 仍写三维原始值，门控只改 status 落库值
- 状态迁移与天数完全解耦：天数只看 today_peak>0 与否，**禁止**按状态升降（active +1 / 降级 -1）推算天数

**peak_count / consecutive_days（沿用旧规则，与三维评分正交）**：
- peak_count = max(历史峰值, today_peak)；创新高时 peak_date=今天
  - **峰值禁止重置**：任何理由（概念集换血 / 新识别 / 爆发例外 / 重跑）都**不得**降低 peak_count——它是生命周期记录，不是当日指标。历史峰值一经记录永久保留
- **consecutive_days = 连续上榜天数**：
  - 今日 today_peak > 0（上榜日）→ 若上一条同名记录连续天数 > 0 且日期间隔 ≤ 10 自然日（周末/节假日/断档可承继）→ 今日 = 上一条 + 1；否则重新起算 = 1
  - 今日 today_peak = 0 → **0**（当日未上榜，无连续可言；16:30 fetch_trend 展示为 "—"）
  - 同名跨概念集刷新**不重置**天数（fading 概念集 → 肝炎爆发仍按同名承继规则判断）；观察线（成色拦截/首日观察期/族内挤出）期不写库，重新上榜时按间隔承继规则判断

### 4. 写库

- **写库前提**：仅通过 2.1 成色过滤的候选可写库（转正 = 连续2天维持+硬门槛全过+评分≥9；或爆发例外当日）；**首日候选一律只进观察线报告，不写库**
- **新子链**（同名无历史记录，或间隔 > 10 自然日）：INSERT status='active', consecutive_days=1, peak_count=stock_count, peak_date=今天, related_sectors 按「数据库」节格式含 concepts+major_concept+sectors；**三维列**：score_heat=3（新子链峰值=今日=100%）、score_fund=theme_fundamentals 当日生效值（无记录先按 2.1 逻辑成色 INSERT 初始化 theme_fundamentals 再回填）、score_tech=当日板块指数技术预估（tech_context：≥MA20且MA20向上=3/≥MA20=2/<MA20但≥MA60=1/<MA60且MA20向下=0；无指数数据→2，16:30 会覆盖）；**P2 新字段**：parent_theme=链族名（如 化工）、related_chains=次属链 JSON（有才写）、signal_peak=today_peak
- **迁移子链**（上一条同名记录存在且间隔 ≤ 10 自然日，含断档/周末恢复）：INSERT 新状态/天数/峰值/三维列（score_heat/score_tech/score_fund 按步骤3计算），related_sectors 按 **R1.1 联动重审**：**核心 sectors 稳定即非换血**（P2 防换血）——concepts/major_concept 用今日新识别刷新写入（供下游 fetch_trend 用新概念映射代表股），**sectors 仅当 P2 身份判定（核心 sectors 交集<1/2 且连续2日）触发旧链闭合时变更**，报告区分离「概念集刷新（非换血）」与「链身份漂移（旧链闭合）」
- **R1.1 sectors 联动重审（写库前强制，替代原样沿用）**：
  - **触发**：上一条 concepts 与今日 concepts 换血（新旧概念交集 < 50%，或任一旧概念被剔除）
  - **动作**：对 sectors 逐板块做**主营语义复核**（与 16:20 守卫同一判据：板块成分股 `theme_constituents.primary_chain` 的 argmax 语义簇 vs 本链语义簇）：
    - 语义主导链属另一现有链族 → 可将该板块移出本链，报告披露「🔄 sectors 语义重审：移除 XX（主导链=YY）」
    - **覆盖不足**（板块成分多为「主营未知」或不在 theme_constituents）→ **保留并披露覆盖不足，禁止据以移除**
    - 语义主导链不属任何现有链族 → 走**独立成链机制**（见 1.6）
  - **禁止**用「成分交集计数/纯度/覆盖率」判定板块归属（count-based 判据在基线不完整时必然误判——军工-航空装备Ⅱ 被误剔即此根因）
  - 重审后若 sectors 为空 → 该子链本轮不写库或按无 sectors 处理（报告披露，下一轮按新识别重走）
- **theme_constituents 成分基线同步（P2 C1，与写库同批执行）**：
  - 每条写库子链：对 Step2 主营归因出的主属股票（primary_chain=该子链）批量 upsert `theme_constituents`（power_idempotent：同 (theme_name, stock_code) 再写行数不变，is_current=1）；biz_evidence=business_cache yw 摘录、biz_report_date=report_date
  - **主营不变不重推**（防 LLM 漂移）：同一股票 primary_chain 沿用上次归属，biz_report_date 未跨期（D2 每日 diff）→ 不 UPDATE
  - **新上市/退市/ST 变化**：白名单事件才允许增删成分；每子链单日变更 ≤成分基线 10%、30日 ≤15%，超限冻结 3 日+人工复核；所有变更写 `theme_constituent_changes` 日志（reason 四类：主营变更/新上市/退市/晋升，evidence + rollback_snapshot）
  - **C5 信号→成分晋升**：连续2日高信号 + 主营复核通过 → 晋升入基线（每子链单日 ≤3只）；**C6 成分休眠**：连续5日 0 上榜 → 标休眠（不剔除，is_current 保留 + 降档标注）
- **theme_fundamentals 同步（与写库同批执行）**：新子链无记录 → INSERT（fund_score=逻辑成色评分, logic_type=评分档位, logic_desc=一句话逻辑, eval_date=今天）；已有记录且逻辑实质变化 → UPDATE（eval_date=今天）；无变化 → 不写
- **迁移补全规则**：最近一条记录 related_sectors 若缺 sectors 字段，迁移时用今日步骤2识别的 sectors 补全（concepts 仍沿用昨日），避免下游 fetch_trend 代表股为 0
- 用 mysql CLI 逐条 INSERT（注意 SQL 转义：概念名含特殊字符时用双引号包 JSON 或用 python -c 一次性生成 SQL —— 不写分析脚本，仅允许生成 SQL 文本）

## 陷阱

- **16:30 之后重跑当日（覆盖模式）必须保留终态列，禁止回退**：若本任务在 16:30 fetch_trend 之后被重新触发（用户 run-now / 补跑），DELETE+重插时**必须把当日已有记录的 `status`/`break_level`/`advice_signal`/`score_tech`/`score_heat` 原样带回**——16:30 不会（当日）二次执行，若按 16:00 初判占位重写，会把这些列回退为默认（bl=0/NULL、T 占位），破坏 16:45–18:45 下游已消费的终态，且次日 16:00 迁移基准（读 prev score_tech）被污染。标准操作：先 dump 当日全列快照（`mysql -B -N -e "... - **报告「未写库」= 当日无 industry_themes 记录（仅观察线文字留痕），≠ ended、≠ 故障**：成因两条叠加——2.2 ≤8 上限挤出（cap_exceed）+ 当日 0~1 上榜验收线落空。状态链断一日，次日重新上榜走迁移基准（间隔 ≤10 自然日承继上一记录终态）+ peak=max(历史,今日) + cd 按「上榜日连续」重新起算（未上榜日=0，不是 +1）。观察线区「预估决策树」列是**假设备**（若写库会给什么状态），供次日对照验线，非 DB 现状。**必做盲区自查**：被挤出链若上一条记录终态为 active/peaking（非 fading/ended），17:30 监控池只扫 fading/ended → 不会登记，形成「当日 DB 无记录 + 池无覆盖」双重缺席。核查 SQL 做集合差：`SELECT theme_name FROM industry_themes WHERE theme_date='<今日>'` vs `SELECT theme_name,watch_status FROM faded_theme_watch`；命中双重缺席者必须在观察线区显式标注「监控盲区（当日无记录且未入池）」，不能只写"未写库"
